## Finding

**Phase 5 costs about 17 µs less a tick in the core than it did in TypeScript.** The profiler's `sim.projectiles`
label, which times all of phase 5 (projectiles, `finishHooks` and the casters), fell from about 31 µs to about 12.6 µs.
The core's own calls take about 3 µs of that, so the crossing, counted conservatively as everything else in the label,
is about 9.9 µs: about 0.21% of the tick.

- **The budget.** The crossing is about 32% of the TypeScript module's cost, over 42.58's generic 10%, but the phase as a
  whole is cheaper than the TypeScript was. It meets [42.58's state-flip exception](42.58-sight-core-adapter.md#the-budget):
  the packed state is the game's own records (the roster rows, the bullets, the paths), the overhead is well under 1% of
  the tick, and this record gives the relative figure beside the absolute one.
- **The whole tick.** Both current runs read about 1.9% above the baseline, and a three-round rerun about 0.7%. The
  difference sits in labels this change does not reach (bots' planning and dynamic navigation, the snapshot, the sync),
  which moved by similar amounts in both directions between runs, while phase 5 itself fell by 17 µs. It is read as
  run-to-run variation, as 42.69 saw ±0.7%, not as a cost of this change; it was not proven to be.
- **Where the crossing goes.** Every call packs the roster (15 numbers a player) and, for projectiles, each player's
  five path points and each bullet's row. The caster run packs the rewind frames only when a caster's view lags, which
  no bot's does, so this bench never packs them. An elimination's own calls (mode 4) are rare and are not separated
  here; they are counted outside `sim.projectiles.core`.

## Method

- **Environment.** The development machine (Windows 11), Node 24, the core built with `npm run core:build` in both
  checkouts. 2026-11-20. Under the exclusive bench lock; other busy share was 3.7–4.7%, below its 25% threshold.
- **The script** was `tests/bench-phase-three.mjs` with its two profiler labels changed to `sim.projectiles` and
  `sim.projectiles.core` and `sim.environment` added, run ad hoc and not committed. Same map cache, warm-up (300 ticks)
  and timed span (600 ticks of `step` plus `snapshot`) as 42.69. The baseline was `git archive a792a495` with its
  `node_modules` a junction to the current checkout's. Order: current, baseline, current.
- **Limits.** Node only; one map and content. A bot match has few projectile hits and kills, so the elimination's
  stop and resume, and its drops' syncs, are barely exercised here; `tests/physics-projectiles.test.js` witnesses them.
  Remeasure with the whole tick at #1214.
- **Test cost.** `tests/physics-projectiles.test.js` now builds real games: 0.6 s isolated (`test:times`, measured
  while the machine was contended), up from bare records that took well under 0.1 s; it gains one case, a kill resumed
  across its drop. The other changed test files lost or simplified cases.
