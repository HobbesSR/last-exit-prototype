# 42.55. The descriptor codec live, against JSON (#1131 stage 2)

Up: [42](42-performance-history.md). Design: [24.1](24.1-wire-encoding-design.md); the contract is in
[24](24-networking-privacy.md#state-encoding). Earlier evidence for the same design:
[42.54](42.54-field-typed-codec.md). 24.1 asks that the adoption match the measured byte savings, and that it
not hide per-view encode cost inside a per-socket loop. This record checks both for the production runtime
(`shared/wire-codec.ts`, `shared/wire-schema.ts`) on the state messages a live room now sends.

## Finding

**The production runtime matches 42.54.** Steady messages are 15.8–16.7% of JSON's bytes, against 16.1–18.6%
in 42.54. In Node, encoding costs 0.78–1.14× `JSON.stringify` and decoding 0.69–0.77× `JSON.parse`.
- **Bytes.** A dev view's steady frame drops from about 4.1 KB to 680 B. A player's drops from 1.8–2.1 KB to
  290–350 B.
- **Encode cost is per view, not per socket.** `broadcast` encodes each distinct (view, keyframe set,
  encoding) payload once and shares it between sessions, as it did for JSON (`server/room-views.js`). So the
  per-tick encode cost follows the number of views, as before.
- **Encode cost is about JSON's.** The small views (contestant and gladiator) are within ±14% of
  `JSON.stringify`. The large ones (dev and spectator) are about 20% cheaper. No encode budget is at risk.

## Results

One room on the harness's pregenerated seed-9 arena (12x6, content as shipped), for 1,200 ticks: a contestant,
a gladiator, the dev view and a delayed spectator. Every match state message each view was sent is included;
waiting-yard frames are not. Keyframes are messages carrying any layer's `all`.

## Method and limits

- **Corpus.** Taken from the messages the server actually delivered, decoded by the harness peer. They are
  re-encoded for timing, which gives the same bytes, since the round trip is exact.
- **Timing.** On the exclusive machine lock. The probe takes the same objects for both encodings, so JSON's
  figure is `JSON.stringify` alone and leaves out the `stateMessage` wrapper both share.
- **One size.** Only 12x6, the room harness's default. The retained 12x6 and 36x18 map caches of 42.47–42.54
  refuse any source change since they were captured, and recapturing them was not needed for this question:
  42.54 measured the same design at both sizes, with the same ratios.
- **Not measured here.** Chrome's decode was measured for this design in 42.54 (0.57–0.72× `JSON.parse`).
  `tests/wire-codec.browser.mjs` keeps Chrome's bytes equal to Node's, and a client plays on the server's
  binary state. Also not measured: process CPU, allocation, and frames on a real network.
- **Bots only.** The bots played no traps, hooks or reloads, as in 42.54. Those families round-trip through
  specimens in `tests/wire-codec.test.js`.
