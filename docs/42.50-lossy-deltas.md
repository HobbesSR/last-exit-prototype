# 42.50. Acknowledged-baseline deltas under simulated loss (#1094)

Up: [42](42-performance-history.md). Design and recommendation: [24.2](24.2-lossy-transport-deltas.md).
This is an offline model over real production projections, not a live measurement or a
protocol change. Scope, budgets and stop rules were posted on #1094 (comment 15355) before
any measurement.

## Finding

Splitting the frame works; sending it all on datagrams does not. Under the **split (S)**, items,
gates and own discovery stay on a reliable stream with today's layers. Everything else goes on
datagrams as a delta against the newest frame the client acknowledged. That meets every budget at
both sizes:
- **Fit:** no steady datagram exceeded 1,200 meter bytes on any profile, and no message fell back
  to a whole frame.
- **Freshness:** p95 staleness is at or below today's everywhere, and lower on every lossy profile.
- **CPU:** the datagram diff costs 21 µs per player view per tick at 36x18 (31.7 µs quantized),
  against a budget of 50.
- **Memory:** a 32-tick history costs 1.2–1.6 MB per room.

**Everything on datagrams (A)** fails at 36x18. It fragments 2–11% of gladiator messages, because
item changes travel with them. It costs 158 µs per view per tick, and a join needs a 40-fragment
whole frame.

Quantizing before comparison cuts S's datagrams by about a third (Sq). Keeping exact everything
client prediction collides with saves 16–17% instead (Sp). That covers the viewer's own player
record and every body without an item (actors and solid props). The prediction witness compared
predicted poses and cuts, not predictor contacts, and it exercised no rotation. It does not qualify
rounding of collision proxies.

## Workload and provenance

Measured 2026-11-16 on Windows, Node v24.15.0, AMD Ryzen 9 5900X, under the exclusive benchmark
lock (`--timing`). Branch `claudecode/1094-lossy-deltas` from `499d4d6`; the figures here are the
rerun after review 863 on PR #1137. The caches are 42.47's retained tuned `chain-live-2` caches:
seed 4217, content-7, source `5cdcd5c`. The driver refuses a cache whose `map/`, `shared/` or
`server/` sources differ, apart from #1133's declaration exports. LF-normalized source hashes are
in each report.

Each run covers ticks 0–1200 with 8 contestants and 3 gladiators, all bots. Every player's own view
and the dev view are projected each tick by the production `match.project`, and today's real
`broadcast` payloads are captured alongside.

Every distinct delta message (330,514 at 12x6 and 330,437 at 36x18) is checked by decoding it
against its baseline: every player-view message (319,248 and 319,242 such checks) and the dev view's
every twentieth tick. Each check compares the rebuilt frame with the projection, as JSON would carry
it, and every one was exact.

**Channels** are 42.48's profiles unchanged: lan, good, typical, wifi and poor, each an rtt, a mean
exponential jitter and an independent loss rate. A **bursty** profile is added: typical's rtt and
jitter, with Gilbert–Elliott outages over 50 ms send slots. 3% of slots are lost, and an outage
lasts a mean of 4 slots (200 ms). An outage loses every packet sent during it.
- **Reliable streams:** a lost 1,448-byte segment stalls its message by max(200, 1.5 rtt) and holds
  everything behind it, as in 42.48.
- **Datagrams:** a message over 1,200 bytes is split into fragments, and it is lost if any fragment
  is lost.
- **Acknowledgements:** the client acknowledges the newest frame it holds on each of its 20 Hz input
  packets, which suffer their own loss. The server deltas against the newest acknowledgement it has
  received while that frame is inside a 32-tick history, and sends a whole frame otherwise.
- **Pairing:** each socket has one fixed trace per direction. A counter-based draw gives every
  (send slot, packet in that slot) a fixed loss and delay, however many packets a candidate sends.
  - Every candidate, today's stream included, meets the same loss and delay for its first packet in
    each slot.
  - Fragments and segments meet the same draws by packet number.
  - S's reliable half uses separate packet numbers in the same slots, so it shares bursty outages.

  The first run drew from one sequential stream, which drifted with fragment counts (review 863);
  its figures are superseded.

**Bytes** are measured with 42.47's dictionary prototype, as a meter. It carries per-value tags,
writes float64 for every non-integer and does no bit packing. It ranks strategies; it is not the
selected codec. On the players+bodies slice, the descriptor codec D took about 0.65–0.7 of this
meter's bytes (42.47 against 42.49), so production datagrams would be smaller still.

Quantized forms carry 24.1's candidate fields as integer quanta, applied before comparison. Sp
leaves the viewer's own player record and every body without an item unrounded. Steady figures
cover ticks 40–1200.

## Freshness

Staleness is the age of the newest complete frame the client holds, sampled 49 ms after each tick
is sent: mean / p95 / p99, in ms. 49 ms is the floor.

| Profile | Today (R), 12x6 | S, 12x6 | Today (R), 36x18 | S, 36x18 |
| --- | --- | --- | --- | --- |
| lan | 49 / 49 / 49 | 49 / 49 / 49 | 49 / 49 / 49 | 49 / 49 / 49 |
| good | 52 / 49 / 199 | 49 / 49 / 49 | 54 / 49 / 199 | 49 / 49 / 49 |
| typical | 87 / 199 / 299 | 73 / 99 / 99 | 94 / 249 / 299 | 73 / 99 / 99 |
| wifi | 161 / 299 / 349 | 118 / 149 / 199 | 180 / 349 / 399 | 118 / 149 / 199 |
| poor | 351 / 599 / 699 | 189 / 249 / 299 | 395 / 599 / 699 | 189 / 249 / 299 |
| bursty | 82 / 149 / 299 | 79 / 99 / 299 | 82 / 149 / 299 | 79 / 99 / 299 |

These are contestant rows; gladiators match within 50 ms except as noted below. Budget 2 is met:
S's p95 is at or below today's everywhere, and its mean is within one tick of today's on lan and
good. A's staleness is within 4 ms of S's.

The one regression is **bursty p99 for gladiators**: 349 ms for S against 299 ms today, at both
sizes. An outage loses datagrams outright, while the reliable model only stalls. That model is
optimistic: it has no retransmission backoff, congestion window or slow start, so a real reliable
stream would do worse under outages. This tail is not separated further.

**S's slow-layer lag** is how far the held items, gates and discovery trail the shown fast frame:
- **p95:** 0 ms on lan and good, 50–100 on typical, 150–200 on wifi, 350–400 on poor, 50 on bursty.
- **p99:** at most 500 ms.

An item body sometimes arrives before its item record. That happened on up to 1.2% of sampled
ticks on typical and wifi, and on up to 3.7% on poor (12x6 gladiator).

**Events** are the last six (`shared/simulation/loot.ts`), so a datagram client misses one only if
every frame holding it is lost. None were missed: 0 of 660 event deliveries at 12x6 and 0 of 990 at
36x18, summed over views, candidates and profiles. The workload has few events.

## Shared views, memory and CPU

**Shared views.** 16 sockets on the dev view, each on its own channel, held this many distinct
acknowledged baselines per tick (mean, max): lan 2, 2; good 2.2, 3; typical 2.8, 4; wifi
3.8–3.9, 6–8; poor 4.3–4.8, 8; bursty 3.4, 7. Each distinct baseline is a separate encode for that
view.

**History memory** is the marginal used heap of retaining the last 32 frames of all 12 views, after
a major collection:
- **Exact:** 1.16 MB at 12x6, 1.62 MB at 36x18. Frozen item and gate records are shared with the
  live match and not counted.
- **Quantized copies:** another 2.08 MB and 2.49 MB. Production would keep only the transmitted
  form.

**CPU** is the median of three rounds, in µs per player view per tick. The baseline is the newest
frame 3 ticks back, the typical median age.

| Work | 12x6 | 36x18 |
| --- | --- | --- |
| Today: `JSON.stringify` of the delivered payload (reference) | 10.5 | 16.9 |
| A: whole-frame diff | 35.7 | 157.8 |
| A: diff, baseline 8 ticks back | 36.2 | 157.5 |
| A: quantize, then diff | 45.8 | 180.5 |
| S: datagram-part diff | 18.8 | 21.0 |
| S: quantize, then diff | 27.4 | 31.7 |

The diff is unoptimized measurement code. A's cost is dominated by comparing every item a view
carries. The meter's own encode is not counted, since the selected codec replaces it (42.49).

## Prediction under quantized delivery (29.2)

The witness is `tools/physics/prediction-network.mjs --quantize=…`. It runs the real game and the
production predictor on its authored map, over 11 of the witness's profiles plus 2 new contact
profiles:
- **wall-slide:** the actor slides along the wall for 74 ticks;
- **proxy-press:** the actor pushes another contestant for 80 ticks, which is a predictor proxy
  throughout.

Contact is counted on exact authority, so both profiles hold it for every variant. It delivers each
frame quantized to 24.1's candidate quanta, with authority kept exact. The table gives each
variant's change from exact delivery, in world units, as the worst over the 13 profiles. Exact
delivery's pre-correction error is 0 except in the profiles built to disagree (background,
reconnect, hidden contact, stale door and proxy-press, at 4.6–5.6).

| Variant | Pre-correction error, p99 rise | Predicted pose moved | Cut differences |
| --- | --- | --- | --- |
| own player record (x, y, heading) | 0.00226 | 0 | none |
| own body (x, y, angle, vx, vy, omega) | 0.00248 | 0.00248 | none |
| proxies (every other body) | 0 | 0.0011 | none |
| all of these | **0.00445** (wall-slide); at most 0.00368 elsewhere | 0.00248 | none |

Budget 5 allowed a rise of 2/512 ≈ 0.0039. Each family alone passes its pose and cut measures, but
all of them together fail on wall-slide, by 0.00055. Most of that rise is the rounding of the own
position the error is measured against, and of the body the predictor starts from.

**What this does not show.** It compares predicted poses and prediction cuts. It does not compare
the predictor's own contacts: the predictor drains them without exposing them, so whether rounding
changed a predicted contact is unmeasured. Body angles and omega are zero throughout, and the
largest velocity rounding was 0.0018. The proxies are an actor and a wall, never a rotated solid
prop, yet the predictor builds each proxy's collision shape from its transmitted x, y and angle.
The map is a synthetic room, not a generated one.

So the witness supports rounding nothing that prediction collides with. Qualifying that needs
predictor-side contact comparison, with rotated solid props, on a generated map (24.2).

## Limits

- The meter is not the codec, and all actors are bots. There is no bandwidth model, and paths are
  symmetric with independent loss, apart from the bursty profile's outages.
- The reliable-stream model is optimistic under loss (above).
- Acknowledgements ride a fixed-phase 20 Hz input clock, not #1096's adjusted one.
- The dev and spectator views are only modelled for shared-baseline counts.
- 72x36 maps and larger rosters are not measured.
- The diff code is unoptimized, so its CPU is an upper bound for the same algorithm.
- The prediction witness's coverage is above.
