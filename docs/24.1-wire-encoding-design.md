# 24.1. Binary wire encoding proposal

Up: [24](24-networking-privacy.md). Design for #1093 under #1092; **proposed,
not adopted or implemented**. JSON remains the live wire format. This document
does not authorize a simulation, input-order, fixture or recording change.

## Recommendation

Use a small, stateless binary codec for already-authorized live messages, with
build-time schema generation from `shared/protocol.ts` and its referenced domain
contracts. Keep live state replication ours. Do not adopt Colyseus state replication
just to change serialization: it would couple this decision to state ownership,
per-view filtering, historical spectator frames and #1094's acknowledgement model.
Colyseus can still own session/room middleware independently.

The measured prototype demonstrates numeric field identifiers, exact integer and
float encodings, and field-specific quantization. It is evidence for the design,
not the production implementation: its dictionary is learned from the workload,
its decoder is reflective Node code, and it does not cover the entire protocol.
[42.47](42.47-wire-encoding.md) owns results, costs and limitations.

The decision for Corey is whether to proceed with this application-owned codec
and the candidate precision below. A lossless first implementation can establish
schema/negotiation/decoder safety before turning on lossy fields. Byte savings
alone do not establish that correction quantization feels acceptable.

## Schema and boundary

`protocol.ts` stays the envelope/type/version authority. The generator follows
its referenced projection, layer, discovery and presentation types; explicit
field metadata beside the projection contracts supplies wire IDs, optional
presence, union discriminants and numeric precision that TypeScript alone cannot
express. The projection allowlists remain the authority for disclosure. Make
their field declarations reusable metadata rather than maintaining an unrelated
second list of private/public fields. Include the observed-player fields and
constructed prediction/physics fields in `simulation/visibility.ts`, not just
the helpers in `simulation/projection-contract.ts`.

Emit checked encoder/decoder code plus a manifest. Assign stable field and variant
IDs explicitly; do not infer them from runtime key order, a particular corpus,
or an alphabetic list that renumbers when a field is added. Fail generation on
uncovered variants, unsupported types, duplicate IDs or missing annotations.
Record types differ by context: a projectile's `dx` is velocity, a shape vertex's
`x` is geometry, and an actor's `x` is a world coordinate. Keyed maps need an
explicit string-key encoding rather than a corpus vocabulary. Preserve null,
omitted values, list order and ID types; never encode undefined as a new meaning.
The present `Record<string, unknown>` state/map paths in `protocol.ts` are not
generatable closed schemas: an implementation must first give those paths
concrete, reviewed projection/map variants, including waiting/ready messages.

A message carries a format tag, schema/wire version and message discriminant,
then bounded lengths, optional-field presence and typed values. The production
format must bound both total bytes and decoded collections/nesting before
allocation, reject unknown versions/tags, duplicate fields, invalid enums,
non-finite numbers, out-of-range integers and trailing/truncated bytes, and use
safe object construction. Enforce the existing inbound validation and size/rate
limits after decoding; binary input creates no new client authority. Never
silently clamp an out-of-range coordinate into a valid-looking location.
JSON strings can contain lone UTF-16 surrogates. Production must preserve them
with an explicit representation or reject them at a reviewed input boundary;
silently replacing them during UTF-8 conversion is not lossless.

## Candidate quantization

All rounding is **projection-only** after disclosure checks. The authoritative
state, hit rewind, inputs and recording frames remain exact. The candidates are
starting precision for a reviewed implementation, not gameplay requirements.

| Field family | Candidate quantum | Maximum rounding error | Treatment |
| --- | --- | --- | --- |
| Player/item/trap/projectile/effect/body/hook world x/y; trap home x/y | 1/256 world unit | 1/512 per axis | Signed integer representation; same rule for an actor's player and body records |
| Player/trap heading and body angle | 2π/65536 radians | π/65536 radians | Prototype uses signed turn quanta; a future wrapped uint16 requires circular boundary tests |
| Body vx/vy | 1/256 world unit per second | 1/512 per component | Signed integer; no assumed small velocity cap |
| Projectile dx/dy (displacement per tick) | 1/256 world unit per tick | 1/512 per component | Signed integer; do not interpret these as body velocity |
| Body omega | 1/4096 radian per second | 1/8192 | Signed integer |
| Collision shapes, local vertices, gate geometry and prediction motor | Exact float64/integer | Zero | Keep collision/tuning identity unchanged initially |
| Tick/sequence/generation/IDs, counters, timers, health, ammo, inventory, discovery, enums and booleans | Exact | Zero | Safe integer or declared discrete type; retain numeric versus string IDs |
| Hazard x, effect radius, trap offset, nested inventory coordinates and heard-cue positions | Exact initially | Zero | Not covered by the prototype's quantized fields; do not infer rounding from a name |

`MAX_PHYSICS_EXTENT = 2**18` is a geometry representability guard, not a proven
bound on every live velocity or coordinate. The prototype uses safe signed
integer magnitudes and refuses overflow. Production fixed-width packing needs
documented bounds or an explicit exact escape representation, including negative
coordinates; saturation is not an escape. Position rounding can move a correction
across a contact boundary despite its small error. Keep own correction state
exact if contact/prediction witnesses reject the candidate.

## Delta, prediction and publication interaction

Keep encoded payloads shared per view and baseline variant as in 24; changing
serialization does not require one encode per socket. #1094 decides how
acknowledged baselines change that sharing. A codec is not a datagram protocol:
large keyframes still require reliable delivery or an explicitly bounded
fragmentation/recovery design under #1095.

For adoption, quantize before comparing transmitted state for deltas so two
values in the same quantum do not generate changes. Preserve kept item/gate
identity caching, or measure the replacement cost. The prototype deliberately
transforms **after** today's layer encoding to isolate serialization; its numbers
do not include this potential reduction in changes or the cost of moving that
boundary. IDs, drop sets and keyframe versions stay exact. Decoding a layer must
reconstruct the canonical transmitted projection, including order and presence.
The current promise in 24 that rebuilt live data equals the unquantized
projection must be explicitly revised for adopted lossy fields.

Prediction consumes decoded values with exactly the same rounding/dequantization
rules as the server's transmitted baseline. Do not round the server solver each
tick to imitate the client. Before lossy own correction is enabled, compare
correction/contact errors and placement, generation, stale-history and tethered
fallback behavior under 29.2. The present size/CPU study is not that acceptance.

Use the same typed record codecs for plain lists in welcome/ready/waiting and
for layer `all`/`set`; keep discovery and physics lifecycle semantics intact.
Public viewer publication consumes its own authorized/delayed projection, with
access/delay and failure policy owned by #1123/#1074/#1098. Reusing projection
rules and `shared/keyed-list.ts` does not make the live wire and recording
`delta-1` one format (17.4 #16). Retain the recording codec and its version.

## Rollout and remaining acceptance

An adoption PR bumps `WIRE_VERSION`, negotiates a named codec before any binary
state and refuses unsupported schema/version combinations. Keep a server-authorized
JSON debug encoding for tools/tests, using the same canonical projection and
precision; never infer a fallback from a failed binary decode. Cover fresh join,
ready, reconnect, plain/layered state, control messages, malformed input and
client-config version skew. HTTP JSON and stored recordings stay independently
versioned.

Before switching the default, require generated-schema coverage, Node/browser
round-trip equality, bounded malformed-input refusal, and browser prediction and
presentation checks under 31. The first implementation must match measured
byte savings without hiding per-view encode cost inside a per-socket loop.
#1094 still needs loss/acknowledgement/history measurements and #1095 still
needs transport evaluation. Those are separate acceptance boundaries, not reasons
to claim a serializer already solves unreliable delivery.

No dependency is added by this proposal or its original-code prototype. The
alternative `@colyseus/schema` is MIT-licensed, compatible with this project's MIT
licence; adopting/serving a pinned version would still require the 21.1 audit and
notices. Its performance was not measured here, so this recommendation is about
ownership and integration cost, not a claim that it is slower.

Primary references checked 2026-11-16: [Colyseus schema definitions](https://docs.colyseus.io/state/schema)
describe schema-based state encoding; [its licence](https://github.com/colyseus/schema/blob/master/LICENSE)
is MIT. Glenn Fiedler's [snapshot compression](https://gafferongames.com/post/snapshot_compression/)
explains precision/bandwidth tradeoffs and acknowledged delta baselines. The
precision values above are this project's proposed choices, not copied bounds
or measured guarantees from those sources.
