Up: [24](24-networking-privacy.md). Direction accepted by Corey on #1093,
comment 15214, after the cross-agent synthesis in comment 15211; verbatim capture
is in [17.4](17.4-live-service.md) #17. **Direction accepted; backend selected: the descriptor codec D
(Corey, 2026-11-17, [17.4](17.4-live-service.md) #17); live implementation unchanged.** #1130's bounded
comparison is in [42.49](42.49-wire-codec-selection.md). At Corey's request, stock protobuf was then measured
head-to-head with D ([42.51](42.51-protobuf-head-to-head.md)). Both were then built from one per-field type
model on the relational wire ([42.54](42.54-field-typed-codec.md)), which recommended D. Corey selected D for
the per-tick state, and #1131 adopts it in stages ("Adoption status" below). JSON remains the live wire format. No simulation,
input-order, fixture or recording change is authorized by this design.

## Adoption status

#1131 adopts D reader first. The client can decode the new encoding before any server sends it.

**Stage 1 (landed).** No server sends binary yet, `WIRE_VERSION` is unchanged, and the live wire is JSON.
- **Runtime.** `shared/wire-codec.ts` is the production runtime: the format, limits and refusals of "Schema
  and boundary" below.
- **Schema.** `shared/wire-schema.ts` types the whole `state` message, both the match frame and the waiting
  frame, as 24.3's proposals 1 and 2 type it. Its schema version is `WIRE_VERSION`.
  - Field names come from the projection owners in `projection-contract.ts`, which now also declares
    `OBSERVED`. A record that disagrees with its owner's declaration fails when the module loads.
  - For records the projection constructs, `tests/wire-codec.test.js` compares the schema with their
    builders.
- **Reader.** `readServerMessage` takes JSON text or D bytes, and `public/room-connection.js` reads both.
  A message it cannot read closes the connection with a notice, without falling back.
- **Checks.**
  - Node: every `state` message of a short room round-trips exactly (waiting, player, dev and spectator
    views, keyframes and change sets). Families bots do not produce round-trip through specimens, and
    malformed bytes are refused.
  - Chrome (`tests/wire-codec.browser.mjs`): it decodes Node's bytes to the same objects and re-encodes
    them to the same bytes. The real client also plays a match over a routed socket that re-encodes every
    `state` message as D, and refuses an unreadable one with a notice.

**Stage 2 (next).**
- Schema closure: 24.3's proposals 3 and 6 and the clear cases of 8, and the roster revision (#1131).
- Directional negotiation, the server writer switch and the JSON debug path, under one `WIRE_VERSION`
  bump.
- Browser flows, and bytes and CPU measured against JSON.

## Recommendation

Keep projection, replication, historical-view selection and baseline policy ours,
with a stateless byte-encoding boundary. Compare a small descriptor/static
DataView slice with a maintained stateless codec before choosing the backend.
Neither a custom generator nor a TypeScript-AST compiler is selected. Do not
take on Colyseus state replication merely to change serialization; that would
also require resolving state ownership, filtering, historical spectator frames
and #1094's baseline model. Session/room middleware is a separate decision.

The measured prototype demonstrates numeric field identifiers, exact integer and
float encodings, and field-specific quantization. It is evidence for the design,
not the production implementation: its dictionary is learned from the workload,
its decoder is reflective Node code, and it does not cover the entire protocol.
[42.47](42.47-wire-encoding.md) owns results, costs and limitations.

Corey accepted a bounded comparison and an **outbound-only, exact-first** rollout
direction. Client inputs remain JSON. Keep every prediction-consumed own state,
remote actor/solid-prop proxy, gate, motor and shape exact initially: rounded
proxies can change local contacts even when the local correction is exact.
Final precision and quantization activation belong to #1094's pre-delta design
and 29.2 prediction qualification. The table below remains a candidate, not
accepted tolerances. Concrete backend, full metadata layout and live switch are
not accepted merely by accepting this direction.

## Bounded selection and follow-through

Use one closed players/bodies family, existing directed/delayed keyframe and
delta envelopes, and a small control/input specimen in Node and Chrome. Derive
disclosure fields from their existing declarations, including constructed fields;
do not introduce another privacy allowlist or close the entire protocol up front.
Compare exact static descriptor/DataView code and a viable maintained stateless
library slice (`msgpackr` records is the contender), with JSON and a limited
JSON+deflate control. Audit any pinned dependency under 21.1 first.

Cap selection at one working day of engineering effort including the decision
record, not two full production generators. Declare byte/CPU/allocation budgets
before timing. Separate steady and first-keyframe costs, Node and browser,
shared-view and many-distinct-baseline workloads; do not preselect #1094 policy.
Count framing, record-table initialization, reconnect behavior, bundle and adapter
burden alongside exact presence/null/ID/number/Unicode and bounded decode safety.
No implicit sequential record dictionary: use self-contained messages or an
explicitly provisioned/versioned table. Name compression-context assumptions and
distinguish compression-only bytes from per-socket transport CPU.

Measure candidate quantized slice size and whether packing can stop at declared
priority boundaries under a byte cap without repeated whole-message encoding.
These probes neither activate precision nor prove whole-frame datagram fit, nor
choose #1094's packing/fragmentation/recovery policy. Stop early for incompatible
semantics/safety or excessive adapter work; an inconclusive result retains JSON
and must not expand the comparison indefinitely. Prefer the simpler maintained
solution when costs meet budgets and are close; custom code needs a concrete fit
or performance/maintenance justification. Return the backend choice to Corey. (Returned through 42.49,
42.51 and 42.54; Corey selected D on 2026-11-17.)

The tracker owns execution/status: #1130 covers selection, #1131 covers selected
lossless outbound adoption and concrete schema closure, #1094 covers lossy deltas
and joint quantization qualification, #1096 covers input timing/possible binary
input, and #1095 covers transport. #1093 records the completed measurement and
accepted direction, not completion of any of those implementations.

## Schema and boundary

`protocol.ts` stays the envelope/type/version authority. The selected schema
mechanism must cover its referenced projection, layer, discovery and presentation
types. Metadata supplies presence, variants and precision where needed; concrete
wire IDs/masks/layout depend on the selected backend. The projection allowlists
remain the authority for disclosure. Make
their field declarations reusable metadata rather than maintaining an unrelated
second list of private/public fields. Include the observed-player fields and
constructed prediction/physics fields in `simulation/visibility.ts`, not just
the helpers in `simulation/projection-contract.ts`.

For adoption, emit checked encoder/decoder/schema artifacts. Any field/variant
identities must be stable across the stated compatibility domain; do not learn
them from a private corpus or silently renumber existing fields. Fail schema
checks on uncovered variants, unsupported types or conflicting identities.
Record types differ by context: a projectile's `dx` is displacement per tick, a shape vertex's
`x` is geometry, and an actor's `x` is a world coordinate. Keyed maps need an
explicit string-key encoding rather than a corpus vocabulary. Preserve null,
omitted values, list order and ID types; never encode undefined as a new meaning.
The present `Record<string, unknown>` state/map paths in `protocol.ts` are not
generatable closed schemas: an implementation must first give those paths
concrete, reviewed projection/map variants, including waiting/ready messages.

A message carries a format tag, schema/wire version and message discriminant,
then bounded lengths, optional-field presence and typed values. The production
format must bound both total bytes and decoded collections/nesting before
allocation, reject unknown versions/tags, duplicate fields, invalid enums,
non-finite numbers, out-of-range integers and trailing/truncated bytes, and use
safe object construction. Enforce the existing inbound validation and size/rate
limits after decoding; binary input creates no new client authority. Never
silently clamp an out-of-range coordinate into a valid-looking location.
JSON strings can contain lone UTF-16 surrogates. Production must preserve them
with an explicit representation or reject them at a reviewed input boundary;
silently replacing them during UTF-8 conversion is not lossless.

## Candidate quantization

All rounding is **projection-only** after disclosure checks. The authoritative
state, hit rewind, inputs and recording frames remain exact. The candidates are
starting precision for a reviewed implementation, not gameplay requirements.

| Field family | Candidate quantum | Maximum rounding error | Treatment |
| --- | --- | --- | --- |
| Player/item/trap/projectile/effect/body/hook world x/y; trap home x/y | 1/256 world unit | 1/512 per axis | Signed integer representation; same rule for an actor's player and body records |
| Player/trap heading and body angle | 2π/65536 radians | π/65536 radians | Prototype uses signed turn quanta; a future wrapped uint16 requires circular boundary tests |
| Body vx/vy | 1/256 world unit per second | 1/512 per component | Signed integer; no assumed small velocity cap |
| Projectile dx/dy (displacement per tick) | 1/256 world unit per tick | 1/512 per component | Signed integer; do not interpret these as body velocity |
| Body omega | 1/4096 radian per second | 1/8192 | Signed integer |
| Collision shapes, local vertices, gate geometry and prediction motor | Exact float64/integer | Zero | Keep collision/tuning identity unchanged initially |
| Tick/sequence/generation/IDs, counters, timers, health, ammo, inventory, discovery, enums and booleans | Exact | Zero | Safe integer or declared discrete type; retain numeric versus string IDs |
| Hazard x, effect radius, trap offset, nested inventory coordinates and heard-cue positions | Exact initially | Zero | Not covered by the prototype's quantized fields; do not infer rounding from a name |

`MAX_PHYSICS_EXTENT = 2**18` is a geometry representability guard, not a proven
bound on every live velocity or coordinate. The prototype uses safe signed
integer magnitudes and refuses overflow. Production fixed-width packing needs
documented bounds or an explicit exact escape representation, including negative
coordinates; saturation is not an escape. Position rounding can move a correction
across a contact boundary despite its small error. Keep own correction state
exact if contact/prediction witnesses reject the candidate.

## Delta, prediction and publication interaction

Keep encoded payloads shared per view and baseline variant as in 24; changing
serialization does not require one encode per socket. #1094's proposal for how
acknowledged baselines change that sharing, and for activating precision, is
[24.2](24.2-lossy-transport-deltas.md). A codec is not a datagram protocol:
large keyframes still require reliable delivery or an explicitly bounded
fragmentation/recovery design under #1095.

For adoption, quantize before comparing transmitted state for deltas so two
values in the same quantum do not generate changes. Preserve kept item/gate
identity caching, or measure the replacement cost. The prototype deliberately
transforms **after** today's layer encoding to isolate serialization; its numbers
do not include this potential reduction in changes or the cost of moving that
boundary. IDs, drop sets and keyframe versions stay exact. Decoding a layer must
reconstruct the canonical transmitted projection, including order and presence.
The current promise in 24 that rebuilt live data equals the unquantized
projection must be explicitly revised for adopted lossy fields.

Prediction consumes decoded values with exactly the same rounding/dequantization
rules as the server's transmitted baseline. Do not round the server solver each
tick to imitate the client. Before lossy own correction is enabled, compare
correction/contact errors and placement, generation, stale-history and tethered
fallback behavior under 29.2. The present size/CPU study is not that acceptance.

Use the same typed record codecs for plain lists in welcome/ready/waiting and
for layer `all`/`set`; keep discovery and physics lifecycle semantics intact.
Public viewer publication consumes its own authorized/delayed projection, with
access/delay and failure policy owned by #1123/#1074/#1098. Reusing projection
rules and `shared/keyed-list.ts` does not make the live wire and recording
`delta-1` one format (17.4 #16). Retain the recording codec and its version.

## Rollout and remaining acceptance

An outbound adoption PR bumps `WIRE_VERSION`, explicitly negotiates directional
formats before binary state and refuses unsupported schema/version combinations.
Keep client-to-server input JSON and its existing validation/rate/size limits.
Keep a server-authorized
JSON debug encoding for tools/tests, using the same canonical projection and
precision; never infer a fallback from a failed binary decode. Cover fresh join,
ready, reconnect, plain/layered state, control messages, malformed input and
client-config version skew. HTTP JSON and stored recordings stay independently
versioned.

Before switching the default, require concrete schema coverage, Node/browser
round-trip equality, bounded malformed-input refusal, and browser prediction and
presentation checks under 31. The first implementation must match measured
byte savings without hiding per-view encode cost inside a per-socket loop.
#1094 still needs loss/acknowledgement/history measurements and #1095 still
needs transport evaluation. Those are separate acceptance boundaries, not reasons
to claim a serializer already solves unreliable delivery.

No dependency is added by this proposal or its original-code prototype. The
alternative `@colyseus/schema` is MIT-licensed, compatible with this project's MIT
licence; adopting/serving a pinned version would still require the 21.1 audit and
notices. Its performance was not measured here, so this recommendation is about
ownership and integration cost, not a claim that it is slower.

Primary references checked 2026-11-16: [Colyseus schema definitions](https://docs.colyseus.io/state/schema)
describe schema-based state encoding; [its licence](https://github.com/colyseus/schema/blob/master/LICENSE)
is MIT. Glenn Fiedler's [snapshot compression](https://gafferongames.com/post/snapshot_compression/)
explains precision/bandwidth tradeoffs and acknowledged delta baselines. The
precision values above are this project's proposed choices, not copied bounds
or measured guarantees from those sources.
