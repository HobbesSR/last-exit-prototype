# 17.2.7. Zone plans and library modules

Up: [17.2](17.2-map-questions.md).

**Zone plans and library modules (2026-10-03, tracker #165).** Should game mode support zones larger than 12 × 6, and what does that ask of set pieces and their placement?
  - "So I'd like to officially support 24 x 12 size zones (or perhaps larger still like 36 x 18) And this has an impact on the authoring of the set pieces with the core elements and then our general placement algorithm of the large, medium, and small set pieces that introduce some structure to the map layout, a design that is hopefully captured somewhere already. We may have to similarly scale the rough areas those set pieces are supposed to cover."
  - "The live game should eventually be able to support a variety of layouts, the diamond pattern being a convenient starting place and gives the expanding and funnelling arc of the game. So in part the 12x6 rule was never intended to be so rigid, but we were getting in to some things that required some kind of shared assumption. This is recorded in a lot of places and what we need is a single source of truth for the diamond zone structure map paradigm. Parameterizable, but with clear authoring responsibilities. We may have to use different tile libraries for each parameterization, or we may need to be able to sort of have things like includes or the like so that set pieces might get placed in different set piece classes for different parameterized libraries. So a library itself may be hierarchal in how it pulls things in so there is reuse across different libraries. And so I guess we didn't setup any of the set piece classes placement rules, which I think we had in the old map but we've focused on making sure the core element set pieces get placed. So if we can import / reuse anything from the old library, or adapt, I think it would be good to see if we can get back to having those placement rules working on the live map, even if the region builders are just passable but marked dummy areas."
    - The placement rules were in fact running on live maps, with the old rules and quotas. What had shrunk was the set pieces: the old library's covered 24 to 50 tiles (enormous), 20 to 36 (medium) and 12 to 24 (small), and the chain library's cover 4 to 10.
  - Chose, from offered options: a named layout that owns the zone grid, mask, tiers, zone-size parameters and placement rules, with libraries saying what they are authored for. Recorded as zone plans in 55; "layout" was already placement's output (51).
  - On where quotas and footprint sizes come from per size: "We may require that these details remain hand authored for each parameterization."
  - On set pieces now: chose bigger footprints, placeholder regions, and keeping the current builders, all three.
  - On live size: chose keeping 12 × 6 live, with larger sizes in generation, the Lab and tests until pacing and per-tick cost are measured.
  - On what a library may do with what it includes: "Perhaps we need something like modules so repeat includes are recognized as the same, while redefinition is an error (but likely one we can refactor). In some cases we may need competing authorship for the same conceptual map structures / elements, and so authorship must carefully break those away from other things meant to be shared."
  - On the old market, industrial and military areas: "use a combination of remapping and imagining new regions types more aligned with what we imaging the map world should be like. At some point I'll like give more specific art direction on the map theme and geometry but do your best for now."
  - Recorded in 55 and 52. The staged work is #166 to #171.
