# Navigation structure measurement (#688)

This directory retains full wire-8 maps and raw `navigation-structure-1` reports
for the three authored sizes. Findings are in [42.23](../../42.23-navigation-structure.md);
definitions and limits are in [51.10](../../51.10-measurement.md).

`manifest.json` pins content revision `b6768e8`, Node version, normalized LF
SHA-256 source digests (including the two new measurement modules), exact
uncompressed map/report hashes, resolved-library hashes, workload parameters
and compact summaries. The working tree added only measurement tooling,
tests and documentation to that content revision. Dependency versions are
pinned by the included `package-lock.json` digest. No timing or machine-capacity
claim is made; CPU/browser metadata is not part of these geometric measurements.

For each width 12, 24 and 36:

- `size-W-1.json.gz` is a complete saved chain map, including its matching
  resolved library and built results. It does not require regeneration to measure.
- `size-W-1-metrics.json.gz` retains both bodies' raw endpoints, statuses,
  straight/path lengths, stratum distributions, qualifying pocket cuts,
  per-region metrics and type/portal-count groups.

Run `node map/tools/navigation-baseline.mts --verify` from the repository root
at this measurement's source. It checks source hashes, regenerates the declared
maps to compare exact content hashes, reads the retained full snapshots,
measures them again and compares every metric, checking measurement did not
mutate the map. It never overwrites evidence. Without `--verify`, the script
captures this fixed workload and refuses to replace an existing manifest.
It is a geometric reproducibility check, not a timing benchmark.

To measure a retained snapshot through the maintained CLI, decompress it first:

```powershell
node --input-type=module -e "import fs from 'node:fs'; import z from 'node:zlib'; fs.mkdirSync('test-results',{recursive:true}); fs.writeFileSync('test-results/688-map.json',z.gunzipSync(fs.readFileSync('docs/reports/issue-688/size-12-1.json.gz')));"
node map/tools/cli.mts navigation test-results/688-map.json --out test-results/688-metrics.json
```

`navigation` also accepts any compatible saved JSON/BSON map, with its embedded
library, through the normal chain reader. A layout-only save is regenerated by
that reader under its compatibility checks; use full results for historical
comparisons. Input files remain unchanged. New content comparisons should retain
new reports and identify changed inputs/sources rather than replacing this
historical baseline.

Validation covers isolated straight/barrier/loop/pocket and ownership-boundary
witnesses, failure summaries, JSON/BSON CLI repeatability and input preservation.
The full fast gate, static/type checks, test-file timing and the unchanged
224-map generation sweep are recorded with the PR. Whole-match, browser and
macro/micro builder suites are outside this tool-only change's affected areas.
