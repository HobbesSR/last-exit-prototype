# 27.1. Tick mechanic inventory (#1281)

Up: [27](27-rust-path.md#the-state-flip). Tracker: #1279. Resolution proposal: #1276. Decisions: [27.2](27.2-tick-architecture.md) (#1282). Milestone benchmark: [42.77](42.77-tick-inventory-checkpoint.md).

This describes `forgejo/main` at `e0d4dcbe`. The live entry is [`stepGame`](../shared/simulation/tick.ts). Rust/WASM runs phase 1 and phases 3–7 via `tick_begin` and `tick_finish`. Node runs phase 2 between the calls, applies the output to its mirror in section order, then runs discovery. The separately callable TypeScript wrappers still dispatch core rules. TypeScript rule copies and compatibility paths are identified where relevant.

In the census, **pre-tick** means the end of the preceding tick plus accepted between-tick changes. A read marked **current** can see the named earlier phase or actor's writes in this tick. A **fact** or **log** is an ordered output operation applied to another store or to the mirror. A **stop** names a point where work must land before the next read. Some stops now run inside Rust and the standalone wrappers can still return a resume cursor. The effects column maps current behavior to #1279's proposed vocabulary. It does not approve any new rules.

Two actor orders appear below. **Stable ID order** (rank) sorts player IDs as strings ([`idRanks`](../shared/simulation/player-store.ts), the core's `rank`). **Roster order** is the index in `s.players`. The roster holds contestants first, then gladiators, with IDs `c0`, `c1`, … and `g0`, `g1`, …, so the two orders coincide while each role has at most ten players (eight contestants by default). They would diverge at `c10`, which sorts before `c2`.

### Ordered output and compatibility paths

- `tick_begin` returns phase 1 rows/facts, sync, hook prepare, admission and commit sections. `tick_finish` returns actions, drag, commit, step, item poses, projectiles, hooks, casters, interactions, traps, sync, finish and sync sections. Each applier uses that section's operation order. `OP_ELIMINATED` and nested syncs can change a record before trailing rows finalize it. The discovery scheduler runs after the finish call and mirror apply.
- Standalone adapters such as `phaseThree`, `phaseSix`, `phase-five.ts` and `hazards.ts` support explicit packed rows or stop/resume for scenario and compatibility callers. Live `tick_finish` packs intents, reads its stores, and carries the relevant continuation inside the call. The TS equipment/combat/transit helpers still serve their own callers. [`27`](27-rust-path.md#the-state-flip) records the migration.
- The effect vocabulary covers gameplay changes. The design also needs an owner and ordering contract for clocks, generations and constraints, ID and scatter allocation, bot and discovery memory, input queues and acknowledgments, rewind, solved paths, discontinuities and publication. A visual or hearing cue can influence later observation or intent in addition to producing an output event.

Expired effects are absent from bot reads and the next published frame. Phase 6 separately ages each unspent trap before checking its trigger. | Define which expirations and cooldown boundaries make a mechanic eligible in the same tick and which clock anchors each rule. |
| D04. Intent-time observations | Phase 2 uses the post-begin, pre-movement world. Bots write their own observations and routing state as they collect. Their later phase 6 door observations and phase 7 discovery cannot change the already collected intent. | Choose the observation snapshot, whether planning may consume knowledge gained during its own turn, and the first tick when each other observation can influence an intent. |
| D05. Commands within one actor | Phase 3 sets aim and selected slot, rearranges, uses the selected bot utility, drops equipment then reserve ammo, advances reload, runs eligible skills then contestant fire, and sets the motor. Thus a completed reload can feed fire, a preceding drop can change the weapon, and a boost activated here can affect this step. | Specify which combinations are atomic, which may invalidate or enable one another, and their precedence when sent together. |
| D06. Drop placement and IDs | Phase 3 uses stable actor-ID order. A successful drop reserves body capacity, space and identity, updates carried and ground sets, and synchronizes before the next drop plan. A refused placement leaves the original equipment or rounds held. | Decide the winner or allocation policy for conflicting space, capacity or identities, and define partial success across multiple drop requests. |
| D07. Physics inputs and timing | Pre-solve motor and hook decisions, queued body changes and impulses, terrain drag and the commit feed a single batched solve. Actor and item poses and swept paths then feed post-solve mechanics. A post-solve warp or impulse cannot change that tick's solved path. | Set the effect cutoffs for the batched solve, and specify which later checks use the solved path, its endpoint, or a subsequent discontinuous position. |
| D08. Hook lifetimes and contact | Existing hooks revalidate before physics. A phase 3 press can cancel a hook before the solve, or launch a tip able to travel in phase 5. Projectile elimination can remove endpoints before tips advance. Actor contact ties use target ID, geometry wins exact ties, and same-role contact consumes the tip. Tentative attachments wait for the next prepare, including revalidation. | Decide contact priority, when a hook request wins against cancellation, death, generation changes or another attachment, and when its constraint first affects motion. |
| D09. Projectile launch and contacts | Contestant fire enters phase 5 in the same tick. Turret fire waits in `pending_spawns` until the next begin. Projectiles age before sweeping. Map contact wins an exact tie with a body. Hit candidates sort by time of impact, projectile ID then target rank. An already dead target is skipped, allowing the same bullet to reach another candidate. | Keep or unify spawn visibility, choose contact and expiry precedence, and decide how a projectile behaves when another effect eliminates its first target. |
| D10. Casting under lethal damage | Projectiles resolve before the hook pass and casters. Casters run by stable ID, warden skill before that actor's gladiator attack. Death suppresses a later actor's cast and phase 6 turn. The warden walks targets in roster order and sets stun after damage, including a lethal hit. | Decide which valid casts and turns survive same-tick death, whether skill precedes attack, and what status writes survive a lethal hit. |
| D11. Rewind and targeting | Casts use the caster's current pose, rewound target positions when available, current target eligibility, and current gates for line checks. Melee's equal-distance choice follows target iteration. Rewind capture is later than movement, interaction and terminal reconciliation. | Specify the time of each predicate and the target tie-break. Set the capture point and fallback when a historical frame or actor entry is missing. |
| D12. Damage, attribution and death | Serial application spends shield before HP. The lethal operation determines attribution. Elimination is applied before continuing, changes status and equipment, can create ground drops, and changes available targets. A gladiator kill can heal its source and reset cooldown before later actions. Neither `Run::damage` nor the elimination reward checks the source's status, so a bullet whose shooter died earlier in the same sweep still damages, logs aggression and earns kill credit. | Choose how multiple damage and status effects combine, who gets kill credit, when death consequences and source rewards are visible, and whether each source emits its feedback. |
| D13. Interact precedence | Within an ID-ordered phase 6 turn, interact tries extraction, charging start, a human full-inventory swap, then a gate, then default gladiator transit. A near gate can consume the attempt without opening. Explicit selectable transit is a separate step, then charging and automatic pickups. Escape and timed transit suppress subsequent charging and pickups. | Specify which gestures can coexist, fallback behavior on a failed interaction, and whether departure or death cancels later effects. |
| D14. Last extraction slot | The first eligible actor in stable ID order spends the slot and the first charged cell, leaves active play, and emits escape before the next actor's check. The victory test runs after all turns and hazards. | Define the winner or split when several contestants request the final slot and whether other same-tick effects still apply to the winner. |
| D15. Contested pickups and partial takes | Earlier actors can consume an item or leave a reduced stack or magazine. Later actors see the partial-take overlay or rebuilt ground list. Automatic pickup uses ground-list sequence, which can change inventory fit and which identities move. A collector resumes after the consumed sequence on a whole take. | Define tie-breaks for whole items, allocation of limited rounds or stack units, and candidate ordering when a collector is capacity-constrained. |
| D16. Swaps and same-tick drop visibility | Swap drafts a take and its outgoing drop atomically. Its committed drop can reach later actors this tick. Manual drops and phase 5 death drops precede pickup turns. Phase 6 hazard drops occur afterward. The dropper's pickup lockout is per item. | Decide when each spawn becomes eligible for each actor, whether a swap may claim capacity created by its own take, and how swaps conflict with automatic takes. |
| D17. Gates, access and occupancy | Earlier turns can open or close a gate and write its discovery state. Later turns, pickups, transit and hazards read the updated gate. Occupancy checks include current actor rows as well as bodies. Automatic access pickup occurs after interact, so a newly collected key cannot pay for that actor's preceding attempt. | Define ordering or resolution of opposing gate requests, which poses and keys count, when collision and sight change, and what a failed attempt teaches. |
| D18. Rails and clearance | Default transit and explicit destination selection read current stations, hazard line, geometry and earlier actor status/positions. Instant land refreshes later turn reads at the new logical pose before body synchronization. Timed departure checks a landing, removes eligibility immediately and retries placement on arrival. | Decide how to arbitrate contested destinations, whether departure reserves a landing, and when destination pose, cooldown and actor removal become visible to rules and physics. |
| D19. Charge and detection | An actor can start and advance charging in one turn if its solved movement and current reach/line pass. Charge completion follows the extraction attempt, so that charge cannot fund the attempt. Sensor reveal follows automatic pickups and sees the actor's current cloak, sneak and position. | Decide whether same-tick start, movement, gate changes, charge completion, extraction, pickup and detection can enable or cancel one another. |
| D20. Hazards versus interaction | Gate changes, escapes and rail departures precede environment and traps, which see the resulting state. Environment uses stable actor-ID order and attempts wall damage before area damage per actor. It enters the actor's wall/area pair using the actor's initial active status and the damage routine rechecks current status. | Set exposure timing for departure, escape and gate changes. Decide how overlapping environmental hits aggregate and which can act on an actor killed by another hazard. |
| D21. Trap order and target choice | Traps execute in authored order over the latest live rows. Mine trigger uses solved movement, blast and flame visit victims in roster order, and turret/spider nearest-target ties follow roster order. Killing a target can change the next trap's target. Spider retention uses leash rules and grapple uses the post-move pose. | Choose trigger and target snapshots, tie-breaks, and whether a trap retargets or still acts when its target dies during the same tick. |
| D22. Mine and spider follow-through | Mine damage and inline eliminations precede the bodies sync and radial impulse, so dead actor bodies are gone and new drops may receive the blast. Spider stun/damage precedes grapple feedback at the resulting actor position, including the lethal path. | Decide who receives a blast impulse, when it is first integrated, and which stun and presentation effects follow through on lethal grapples. |
| D23. Terminal result and observation | Phase 7 synchronizes, tests extraction slots, active contestants and time, strands remaining active contestants when finishing, synchronizes again, and records rewind. Discovery then sees the post-finish statuses and skips stranded contestants. Node records after discovery and may only broadcast the newest frame of a catch-up batch. | Set the terminal cutoff for final-tick mechanics, observer eligibility, rewind and the recording/projection boundary. Preserve or explicitly revise the per-tick frame and latest-state delivery semantics. |
| D24. Event and identity ordering | Stages and nested stops allocate serials and item identities as they run. Node applies logs in generation order before dependent rows. Begin sync can remove hooks before hook output is interpreted, and in-run item removals, swaps and death facts must precede dependent mirror writes. `event-records.ts` retains only the newest events. Some stages walk actors in stable ID order and others in roster order; these coincide at the current roster size. | Choose one actor order for every stage, or state where each applies. Decide the deterministic order needed for IDs, drops/scatter, event credit and retention, and publication. State which ordering is externally observable and which can disappear with the mirror, while preserving atomic references at apply. |
| D25. Physical placement, resources and overlapping surfaces | Body reconciliation removes inactive actors first, places active actors in stable ID order, then handles gates, items and hooks. Launches have priority over waiting item records, with capacity reserves. Impulses precede pending attachments. Motor surfaces and floor drag each use priority then surface ID to break overlaps. | Define placement and capacity arbitration, overlap priority, and mutation/admission ordering, including whether a logical item can be claimable while awaiting its body. |
| D26. Observation ordering and planning budget | Discovery and dynamic detour work use roster offsets to stagger eligibility. Bots spend a shared detour budget in roster order. Detour blocker distance ties preserve observation order (actors then props, each by ID). Remembered loot and exploration ties can inherit discovery insertion order. | Decide whether to retain the stagger and budget rules, which stable index and fairness policy to use, and how blocker and discovery-derived target ties should break. |
| D27. Cues and captured state | Phase 3 hearing uses pre-movement listeners and reaches later intents. Views can read live cues and discovery after the tick, alongside the captured frame. Snapshots consume physics discontinuities at their designated capture. | Decide when cues are computed and become visible, how projections pair current memory with captured frames, and which frame carries each discontinuity. |
