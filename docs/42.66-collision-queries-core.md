# 42.66. The map's collision queries in the Rust core (#1233)

Up: [42](42-performance-history.md). Design: [27](27-rust-path.md#the-state-flip), step 5b.2. The queries are
`rust/core/src/collision.rs`, bound in `shared/sight-core.ts`. Nothing in the tick calls them yet, so the tick is
unchanged; #1234 moves the callers. `tests/collision-core.test.js` held them equal to the TypeScript throughout.

## Finding

**The core answers a query about four times faster than the TypeScript. Per call from JavaScript, the open-gate mask
eats most of that.** On the 24x12 map (seed 4217: 13,982 obstacles, 421 gates), per call:

| Variant | `canOccupy` | `reachClear` | `lineClear` |
| --- | ---: | ---: | ---: |
| TypeScript (`movement.ts`, `sight.ts`) | 0.86–0.94 µs | 1.33–1.57 µs | 0.78–0.86 µs |
| The core through the adapter, writing the mask each call | 0.78–1.05 µs | 0.93–0.99 µs | 0.81–0.86 µs |
| The core called directly, the mask written once | 0.20–0.22 µs | 0.34–0.37 µs | — |
| Writing the 421-gate mask alone | 0.53–0.58 µs | | |
| One empty call (`adapter_version`) | 0.004 µs | | |

- **The crossing itself** is the empty call, about 0.5% of the TypeScript's `canOccupy`.
- **The mask is state JavaScript owns until the flip** (#1214): the gates' `open` flags, read live. Writing it costs
  about 1.3 ns per gate. Through the per-call adapter, which writes it every time, `canOccupy` costs about what the
  TypeScript does and `reachClear` about a third less.
- **#1234's callers write it once per batch.** The landing's ring search and the admission run in the core and make
  many queries per mask. A lone query a tick still pays the whole write, about 60% of one TypeScript `canOccupy`. That
  is over 42.58's 10%, and about 0.01% of the 4.5 ms tick (42.65), so it falls under
  [42.58's state-flip exception](42.58-sight-core-adapter.md#the-budget): JavaScript owns the state and the flip
  removes the packing. #1234 records the figures for the batches it actually makes.
- **An ignored gate is the only per-call branch.** Comparing every gate's ID on calls that ignore none had doubled the
  mask's cost; the adapter now compares IDs only when `lineClear` is given one.

**The upload is once per map:** the playable cells and every collider, flattened from movement's own index. On this
map it takes 23–29 ms in JavaScript, after the TypeScript's index exists, plus the copy. Sight's upload already took
15–30 ms. #1234 should prepare it with the map, as `prepareMovementGeometry` prepares the TypeScript's index, rather
than at a match's first query.

## Method

- **Environment.** The development machine (Windows 11), Node 24, the core built with `npm run core:build`.
  2026-11-20, under the exclusive bench lock, other load 2–13%.
- **The script** was ad hoc, not committed. It built the 24x12 map for seed 4217 with the shipped content, opened every
  third gate, and drew 4,000 points over the map (radii 12, 16 and 24 in turn) and 4,000 segments of up to 300 units
  each way. Each variant ran all of them; seven rounds rotated the order, after five warm-up passes, and each run
  reported the per-variant median. Three runs; the ranges span them.
- **The direct calls** used handles built from the same tables the adapter uploads.
- **The upload** was timed on fresh copies of the map after the TypeScript's index was built, four times.

## Limits

- **Uniform points.** Placement searches near walls and props, where more colliders are near each point. Both copies
  test the same candidates, so the ratio should hold, but #1234 measures the real distribution.
- **Node only.** The browser runs the same module; its adapter overhead was not timed.
