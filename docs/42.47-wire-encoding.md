# 42.47. Live wire encoding comparison (#1093)

Up: [42](42-performance-history.md). Proposed contract:
[24.1](24.1-wire-encoding-design.md). This is a serialization study, not a live
protocol change or prediction qualification.

## Finding

On the tuned `chain-live-2` workload, dictionary binary uses 42–45% of steady
JSON bytes across the eight size/view combinations. Field-specific quantization
reduces that to 37–43%. The reflective binary encoder/decoder costs more CPU
than JSON. Most of the saving comes from binary representation and numeric field
identifiers; quantization is a smaller additional gain and is not uniformly
smaller on keyframes. Recommend an application-owned generated codec, retaining
exact correction data for its first implementation until lossy prediction has
separate evidence (24.1).

## Workload and provenance

Measured 2026-11-16 UTC on Windows, Node v24.15.0, AMD Ryzen 9 5900X. Both sizes
use seed 4217, content-7 and the final #1127 loot tuning from merged main
`78255e4`. Runtime/generation source is the branch merge
`5cdcd5cbad63397d011f951d4196e03f0e2c0bbb`; generation/runtime sources had no
uncommitted changes. Driver/codec changes were uncommitted and are pinned by
their SHA-256 in each raw report (driver `271bd96a…`, codec `1ad28dcc…`).
Both reports contain the full hashes, cache generation timestamp and source,
dictionary, population/error counts, corpus and delivered-stream digests, all
timing rounds and contention stamps.

Maps were **freshly generated after #1127**, using the production map worker,
including portal graph and prebuilt navigation tiles. Neither the earlier #1086
caches nor the pre-tuning pilots were used. Cache acceptance compares committed
and working runtime/generation sources against the recorded source revision;
`content-7` or `chain-live-2` alone is insufficient freshness evidence.

Run order: 12x6, then 36x18, sequentially under the exclusive benchmark lock.
Neither final run was contended (external busy shares 5.25% and 3.86%, threshold
25%). Earlier preliminary runs were discarded from the findings. Each final
run advances ticks 0–1200, no early finish, with four simulated receiving
sessions: one contestant, one gladiator, an undelayed developer and the existing
60-tick-delayed spectator. The actors remain bots; this is not a human-input
trace. The real production `broadcast` creates every payload, with normal layer
and discovery tracking. Every delivered JSON frame is rebuilt through layer and
discovery decoders and compared with its authorized projection before sampling:
4,804 successful reconstructions per size. Maximum directed-view populations
were 11 players, 80 bodies, 232/2,006 items at 12x6/36x18, and 3/8 projectiles.
There were no traps, tethers or hook flights in these runs.
The prototype assumes well-formed Unicode strings; lone UTF-16 surrogates are
not round-trip safe through its UTF-8 conversion. This limitation excludes it
from live use without the explicit string treatment in 24.1.

Every twentieth tick supplies a timing/size sample: 61 per view, 244 per size.
The samples are actual delivered messages but **not a replayable delta stream**,
since unsampled ticks still advance baselines. Each sampled message round-trips
exactly through lossless binary; the quantized variant matches its explicitly
rounded reference, and every changed numeric field is independently checked
against its half-quantum error bound. Optional fields, ID types and array order
survive. Sampled player/body coordinate errors reach 1/512 world unit; heading
error remains below π/65536 radians. Body angle and omega were zero throughout,
so their zero observed error is not useful rotation coverage. See raw per-field
counts, magnitudes and errors rather than inferring coverage from the table.

## Bytes

`First` includes initial layer keyframes but excludes welcome/map delivery.
`Steady` is the arithmetic mean of ticks 20–1200, including any sampled later
rekeys; it is not a full-stream bandwidth integral. Sizes exclude WebSocket,
TLS, transport and compression overhead. JSON is counted as UTF-8 bytes.

| Size/view | First JSON / binary / quantized bytes | Steady JSON / binary / quantized bytes |
| --- | --- | --- |
| 12x6 contestant | 17,889 / 7,773 / 7,626 | 3,484 / 1,532 / 1,387 |
| 12x6 gladiator | 17,932 / 7,939 / 7,800 | 2,255 / 940 / 849 |
| 12x6 dev | 55,393 / 26,099 / 25,490 | 5,963 / 2,582 / 2,194 |
| 12x6 spectator | 55,393 / 26,099 / 25,490 | 5,797 / 2,508 / 2,140 |
| 36x18 contestant | 103,433 / 46,848 / 46,675 | 5,212 / 2,258 / 2,096 |
| 36x18 gladiator | 100,704 / 45,916 / 45,970 | 4,104 / 1,830 / 1,755 |
| 36x18 dev | 320,185 / 163,423 / 166,700 | 7,227 / 3,195 / 2,825 |
| 36x18 spectator | 320,185 / 163,423 / 166,700 | 7,006 / 3,094 / 2,742 |

The corpus-derived key dictionary costs another 869/889 JSON bytes once per
schema/session if transmitted. It is excluded from per-frame totals, not free.
A real generated schema would ship its manifest with the client rather than
learning fields from one match. The prototype includes per-value type tags and
object field IDs, uses UTF-8 strings, safe integer magnitude varints, float64
otherwise, and does no bit packing, enum/string interning or compression.
Already-integer large coordinates can need more varint bytes after scaling:
the 36x18 directed first quantized frame is 2% larger than exact binary.
This result does not establish that fixed-width generated fields share that cost.

## Encode/decode cost

Three rounds alternate JSON/binary/quantized and reverse order after warming
all modes. Each encode or decode batch cycles the entire view sample for at
least 200 ms; this avoids tiny batches dominated by process CPU timer resolution.
Each cell below is median **encode/decode microseconds per sampled frame**:
wall followed by process CPU in parentheses. Process CPU can include GC helper
threads. Full rounds, including individual iteration counts, are retained.

| Size/view | JSON wall (CPU) | Binary wall (CPU) | Quantized wall (CPU) |
| --- | --- | --- | --- |
| 12x6 contestant | 12/13 (12/14) | 23/55 (23/52) | 34/62 (39/62) |
| 12x6 gladiator | 7/10 (7/11) | 17/39 (16/40) | 21/44 (21/44) |
| 12x6 dev | 28/26 (28/26) | 43/99 (43/98) | 57/118 (58/119) |
| 12x6 spectator | 25/23 (25/23) | 40/102 (41/103) | 54/110 (55/111) |
| 36x18 contestant | 20/23 (20/23) | 45/106 (44/107) | 54/119 (57/115) |
| 36x18 gladiator | 15/19 (16/20) | 39/91 (38/90) | 46/99 (46/98) |
| 36x18 dev | 34/40 (35/41) | 80/187 (81/185) | 108/213 (107/209) |
| 36x18 spectator | 35/42 (36/41) | 80/184 (80/185) | 105/225 (104/224) |

These are Node encode/decode costs starting with parsed production message
objects. JSON encode produces a string; binary encode produces a Buffer. Socket
UTF-8 conversion/framing is not timed. Binary decode currently copies input and
defines object properties reflectively. Quantized encode/decode additionally
clones and scales record fields. None of these is generated-code/browser CPU,
full room-tick cost or a claimed speedup. The worst measured mean encode is
about 0.11 ms per view, but it includes first-frame samples amortized among
steady samples, so it is not a first-keyframe latency bound.

Quantization is performed **after** existing layer comparison to isolate
serialization. These numbers do not measure the CPU or changed-entry savings
of comparing quantized records before delta encoding. They exclude projection,
layer/discovery encoding and rebuilding, validation, transport, rendering and
prediction. The codec deliberately keeps simulation and recordings untouched.
This workload covers real gameplay messages at both required sizes; it does not
cover the whole protocol, rotation-heavy/hook cases, late match, network loss,
browser behavior or live human input. Those boundaries are explicit adoption
work in 24.1, not results implied by this study.

## Raw evidence and reproduction

- [12x6 final report](reports/wire-1093-12x6.json)
- [36x18 final report](reports/wire-1093-36x18.json)

From this source, choose **new, absent cache paths**; generation refuses to
overwrite an old cache. `--generate` takes the normal map worker path. Omit
`--generate` to repeat against a matching retained cache.

```powershell
node tools/perf/wire-encoding.mjs --generate --size=12x6 --maps-cache=test-results/wire-new-12x6.v8 --out=test-results/wire-new-12x6.json --timing
node tools/perf/wire-encoding.mjs --generate --size=36x18 --maps-cache=test-results/wire-new-36x18.v8 --out=test-results/wire-new-36x18.json --timing
```

Runtime/generation paths must be clean before cache generation. Default options
are `--ticks=1200 --stride=20 --repeats=3 --seed=4217`. Without `--timing` the
driver runs correctness/byte checks under a shared lock and skips CPU rounds.
It remains an opt-in witness outside routine test tiers; no tests were added or
slowed by this study. The separate prototype codec has no dependency and no live
server/browser import.
