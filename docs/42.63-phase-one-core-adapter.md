# 42.63. Tick phase 1 in the Rust core: pack, run and unpack per tick (#1212)

Up: [42](42-performance-history.md). Design: [27](27-rust-path.md#the-state-flip), step 4 (D1). The rules are
`rust/core/src/phase_one.rs`; `beginTick` in `shared/simulation/phase-one.ts` packs the players, effects and stations,
makes one call, and applies the result to the game, which stays in JavaScript. `characterization-physics`, its
`-bots` variant and `tests/tick-phases.test.js` passed unchanged.

## Finding

**The crossing costs about 1.8 µs a tick: over 42.58's relative budget, and negligible in the tick.**

| Phase 1's rules (tick, hazard wall, effect lives, respawn and arrival checks, timers) | Per tick |
| --- | ---: |
| TypeScript, as `tick.ts` and `tick-rules.ts` ran them | 1.40–1.46 µs |
| Core call, with packing and unpacking | 3.18–3.40 µs |

- **The budget (42.58): crossing overhead at most 10% of the module's TypeScript cost per tick.** Here the overhead is
  about 130% of it: the rules are a few comparisons and decrements per player, so packing 16 words a player and
  writing the fields back costs more than running them. 42.58's budget was set for modules whose compute dwarfs the
  crossing, as sight and discovery do.
- **In the tick it is nothing.** 1.8 µs is about 0.06% of the 2.8 ms mean tick on this map (42.58), and under 0.004%
  of the 50 ms tick at 20 Hz.
- **No flat view helps.** 42.58's remedy is to return a view the caller reads, but the callers are the game's own
  player and effect records, which only JavaScript holds. That is the case 42.58 names as the evidence for flipping
  state ownership. The flip is already planned: step 6 (#1214) keeps the state in the core, and the packing goes.
- **A normal tick is one call.** The run stops for JavaScript only when a respawn needs the stations' clearance or a
  transit lands; neither happened in the measured ticks.

## Method

- **Environment.** The development machine (Windows 11), Node 24.15, the core built with `npm run core:build`.
  2026-11-19, under the exclusive bench lock.
- **The script** was ad hoc, not committed: one game on a 24x12 live map, seed 4217, the shipped content, stepped 300
  ticks (11 players, 6 stations, no live effects at that tick). Then 20,000 calls per variant, with the tick, effects
  and one timer restored before each call so every call does the same work, and 7 rounds after a warm-up. The
  TypeScript variant was the retired loop copied into the script. A restore-only baseline was 0.02 µs.
- **Three runs**, each reporting the per-variant median of its rounds.

## Limits

- **Node only.** The browser does not run the tick.
- **No effects were live.** Each live effect adds one word in and one write back.
- **Respawns and landings were not timed.** They add a call each, and the queries JavaScript already ran.
