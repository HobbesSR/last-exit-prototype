# 42.72. Tick phase 6's per-actor loop in the Rust core (#1230)

Up: [42](42-performance-history.md). Design: [27](27-rust-path.md#the-state-flip), step 5e.1. The work is
`rust/core/src/phase_six.rs`, driven by `shared/simulation/phase-six.ts`. `characterization-physics`, its `-bots`
variant and `tests/tick-phases.test.js` passed unchanged.

## Finding

**The phase's crossing is about 28–30 µs a tick, about 0.6% of the tick, under 42.58's state-flip exception.** The
profiler's `sim.pickups` label times the whole per-actor loop: interactions, transit, charging and pickups, with
pickups' syncs. In the final interleaved comparison it was 34.6–35.7 µs against the TypeScript's 25.2 µs. The core's
own calls (`sim.pickups.core`) take about 6.5 µs of that. Everything else in the label is counted as crossing,
conservatively, as 42.69 and 42.71 do.

| 24x12, seed 4217, median of five rounds | Current run 1 | Baseline (`cccc345a`) | Current run 2 |
| --- | ---: | ---: | ---: |
| Whole tick with snapshot | 4.850 ms | 4.695 ms | 4.791 ms |
| `sim.pickups` (the per-actor loop) | 35.684 µs | 25.198 µs | 34.584 µs |
| `sim.pickups.core` (the core's calls) | 6.394 µs | — | 6.603 µs |
| `sim.pickups` minus the core (conservative crossing) | 29.759 µs | — | 28.348 µs |
| Crossing / whole tick | 0.614% | — | 0.592% |

- **The budget.** The crossing is about 115–120% of the TypeScript phase's cost, well over 42.58's generic 10%. It meets
  the [state-flip exception](42.58-sight-core-adapter.md#the-budget): the packed state is the game's own records
  (the actors, their inventories, the ground records in reach, the gates' masks), and the overhead is under 1% of
  the tick.
- **The whole tick.** The two current runs read 2.1–3.3% above this baseline. A second interleaved run that reported
  every profiler label reversed that: the baseline at 4.836 ms, between current runs at 4.661 and 4.810 ms. There,
  `sim.pickups` read 31.4 µs in the baseline and 33.5–39.8 µs current. The labels that moved between runs, in both
  directions, were bots' planning and repath (`sim.bots.plan`, `sim.repath`), which this change does not reach. The
  gap is read as run-to-run variation, as 42.71 read its own, not as a cost of this change. It was not proven to be.
- **Where the crossing goes.** In the bench, bots press interact on most ticks: about 10.5 actors take a turn each
  tick, 7.5 of them interacting. A segment profile of one call, taken with the profiler's own overhead, put the
  remaining cost at:
  - packing the turns, about 11 µs;
  - one pass over the 421 gates for the open and lock masks, about 12 µs;
  - the grid queries for records in reach, about 10 µs, which the TypeScript also paid;
  - applying the facts, about 2 µs.

  Reading the gates' fields is slow on this bench's map, which is deserialized from a v8 cache; that alone was about
  8 µs for the locks.

## What brought it down

The first working version's crossing was 50.0–53.3 µs, 1.01–1.09% of the tick, over the exception's ceiling:

| Change | Effect |
| --- | --- |
| Trimming near records to a box around the pickup reach, counting the free label phases the call can use, and writing the open mask only when a rule reads a gate | Barely measurable: crossing 50.4–51.0 µs |
| **The core finds the gates near an interacting actor** in its own gate set's buckets, instead of Node's string-keyed `gatesNear` (about 15 µs a tick). Positions and kinds cross once per gate set; locks go into a mask | About 15 µs |
| **An interacting actor sends its inventory** only when it carries a cell or can swap; gates and transit never read it | About 3 µs |
| **The input goes into a reusable typed buffer** instead of a growing array | About 12 µs on packing |
| **The open and lock masks are written in one pass** | About 2 µs |

## Method

- **Environment.** The development machine (Windows 11), Node v24.15.0, the core built with `npm run core:build` in
  both checkouts. 2026-11-20. Under the exclusive bench lock; other busy share was 5.7–8.4%, below the 25% threshold.
- **The script** was `tests/bench-phase-three.mjs` with its two profiler labels changed to `sim.pickups` and
  `sim.pickups.core`, run ad hoc and not committed. It uses the same map cache, warm-up (300 ticks) and timed span
  (600 ticks of `step` plus `snapshot`) as 42.69. A second ad hoc copy reported every `sim.*` label.
- **The baseline** was `git archive cccc345a` (main after #1244), with its `node_modules` a junction to the current
  checkout's. Run order: current, baseline, current.
- **Limits.** Node only, with one map and content. A bot match swaps nothing, since bots never swap, and picks up
  little; `phase-six-core`, `item-instances` and `item-scatter` witness those paths. Remeasure with the whole tick at
  #1214.
- **Test cost.**
  - `tests/phase-six-core.test.js` is new: 0.5 s isolated (`test:times`). It holds the pickups against the retained
    TypeScript transfer and the gate choice against `nearbyGate`, and checks the sensors.
  - `tests/item-scatter.test.js` went from 0.4 s to 0.5 s: its two swap cases now build real games.
  - `tests/ground-items.test.js` stayed at 0.7 s; its partial-pickup case also builds a real game.
