## Boundary and witnesses

The live player predicts its motor in a fresh projected Rapier island. Authorized
remote bodies are fixed correction-tick proxies; hidden motion and unknown
forces wait for authority. The eight-tick replay limit and bounded geometry,
history and stale-state fallbacks are defined in 29.2. The client does not
speculatively apply damage, pickup, inventory changes or attachments. There is
no exact full-world rollback or cache-restoration claim. Recording schema,
rules and content identities are unchanged: this is a live client contract.

`tests/physics-prediction.test.js` exercises real WASM motion, acknowledgement
replay, duplicate refusal, authorized and omitted blockers, static walls, gaps,
profile/generation/placement changes, tether fallback and bounded stale/history
handling. `physics-prediction-contract` checks closed own-only motor tuning and
shared motor arithmetic. Existing body interpolation tests retain shortest-angle
and lifecycle/gap coverage. The Chrome prediction witness runs the production
module with delayed corrections. The playback browser witness additionally
checks that the local sprite and eye use prediction while a correction across
a known wall snaps; playback still loads no engine. Camera, sprite, fog and
cover share that eye.

The PR review regression walks past a stationary prop with three pending inputs,
crossing both edges of the nearby replay horizon without a prediction cut.
Proxy membership is rebuilt at each correction; range entry/exit no longer
discards pending replay. Motor fallback tuning comes from the shared motor owner,
and the projected speed ceiling uses the adapter's engine-free motion bounds.
Prediction/presentation time thresholds share `physics-prediction-limits.js`.

## Scheduled network evidence

Run `node tools/physics/prediction-network.mjs --write-report` under the shared
benchmark lock. The [retained raw report](reports/physics-441-network.json)
pins the source hashes, backend/WASM, machine/runtime, map, motor tuning and
run settings. Each profile runs the real authoritative game and production
predictor for 85 ticks on a small authored rectangular map, with ordered reliable
delivery scheduled by a synthetic clock. It covers 0/50/100/200 ms RTT, jitter
and stalls, omitted application frames, background resume, reconnect, queue
trimming/repeats, withheld contacts and stale door memory.

Across profiles, the retained report records correction-call and input-call
CPU percentiles and maxima separately, including allocation tails.
The review rerun's largest profile p95 values are 0.614 ms for correction and
0.762 ms for input; maxima are 2.803 and 4.542 ms. Low p95 values do not bound cold-call tails.
These samples include cold calls and allocation tails, with no warm-up pass.
Total input plus projected-frame JSON is 132,480 to 146,687 bytes per profile.
The burst witness reaches the four-input server queue, trims 11 oldest inputs
and records six repeated-input ticks. The gap witness records a gap cut;
background/reconnect witnesses recreate prediction and reconnect resets the
server queue. Each condition has an executable assertion.

This scheduling lab is not a real network or browser frame-budget qualification.
Hidden-proxy omission and stale door state are explicitly injected privacy
stress conditions. Frame byte counts are uncompressed projected JSON before
layer encoding; they do not include transport overhead or compression. Error
against current authority includes legitimate in-flight delay; correction error
uses predicted and authoritative poses at the correction tick when a retained
prediction exists. Settling counts ticks from the first neutral input (tick 60)
to three consecutive samples within one world unit. Measurements do not establish
human feel or a production capacity envelope.
