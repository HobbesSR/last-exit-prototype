## Implemented outward contract (#1153)

- Live JSON uses `WIRE_VERSION = 4`. `state.self` holds the viewer's private fields;
  `state.players` contains only other authorized records, keyed by `playerIdx`. Metadata
  (`id` connection label, `name`, `role`, `kit`, optional `seat`) lives in the envelope's
  ordered `roster`; reliable `seats { roster }` updates precede the corresponding state.
  Delayed spectators receive metadata from their captured tick, never today's roster.
- Numeric body IDs and discriminated owners, numeric item identities, tethers and flights
  cross the projection boundary. The temporary item/presentation adapters are removed.
  Connection labels and private PhysicsWorld sort keys remain strings. Captured diagnostic
  physics retains those deterministic keys; it is never sent live.
- Active actor/physical-item `x`/`y` occurs only on the body. Bodyless records retain their
  fallback pose. `shared/relational-frame.ts` joins display records and maintains
  direct actor/item/prop associations. Playback normalizes schema-10..19 legacy values at
  this same boundary without changing stored archive values or integrity checks.
  Unchanged numeric bodyless records pass through directly. Converted records are cached
  by source record and body/geometry/metadata; frame joins and owner tables are shared
  across server views. Replays retain the reader's record sharing instead of expanding
  every item and gate for every retained frame. Ground publications retain their grid.
- `map.gates` retains full ordered geometry and `gateIdx`; state carries only
  `{ gateIdx, open, locked }`. Client and replay merge dynamics into retained geometry.
  `frame-layers.ts` compresses body shapes against the exact target keyframe generation;
  newly introduced/regenerated bodies retain shape until absorbed. No shape dictionary.
- Five structured event kinds capture event-time participants. `shared/events.ts` formats
  them with the English default and legacy text fallback. A later seat change cannot
  rewrite earlier attribution.
- New recordings declare schema 20 and minimum reader 20; the current reader floor
  remains 10. Rules stay `last-exit-0.8-physics`: this is a representation change, supported
  by unchanged gameplay/private-world continuity evidence, not a gameplay recapture.
  The intentional projection fixture update and provenance are in the fixture README.

The detailed accepted contracts below remain normative. Earlier checkpoint descriptions
explain the implementation sequence; their temporary adapters no longer run outward.

## Why this precedes #1130 and #1131

[24.3](24.3-wire-data-model.md) exposed two structural problems with benchmarking or
closing a binary wire schema directly over today's JSON-shaped projections:

1. **String-assembled relations across lookup, storage and transfer.** Players (`c0`,
   `g0`), items (`item-42` vs `instance-42`), gates (`door-12`), physics bodies
   (`actor:c0`, `item:item-42`, `prop:crate`) and hooks (`hook:g0`) are linked by
   concatenated strings, linear `.find()` scans and mixed string/number declarations.
2. **Repeated static geometry and pre-formatted English event text.** A 36x18 dev view
   carries 787 gates whose `x`, `y`, `w`, `h` and `buildingId` resend on every
   keyframe, bodies repeat unchanged `shape` descriptors on every update, and `events`
   transmit pre-formatted English sentences (`"Mica eliminated by Rook"`).

Settling the engine's relational strategy, static geometry delivery split and structured
localized events before `#1130`'s field-typed `D`-versus-`protobuf` comparison ensures
the benchmark measures the actual target data model rather than string parsing and
duplicated geometry.

## Relational representation classes and index criteria

Every simulation and projection association falls into one of three physical forms.
A relation belongs in the tightest class whose invariants hold across visibility,
deltas and lifecycle.

| Class | Physical form | When to use (required invariants) | Entities in Last Exit |
| --- | --- | --- | --- |
| **1. Implicit dense index (`0 .. N-1`)** | Positional array index (`uint`) | Closed, fixed-cardinality, fixed-order collection for the match or map; every authorized viewer shares the same slot table or dense map index | **Player seats/actors** (`PlayerIdx` in fixed match roster), **static gates** (`GateIdx` in `map.gates`), **inventory slots** (`0 .. SLOT_COUNT-1`), **closed content/enum tables** (`kits`, `weapons`, `roles`, `phases`, `ammoFamilies`, `effectKinds`, `bodyKinds`, `shapeKinds`, `eventKinds`) |
| **2. Stable monotonic numeric ID (`uint`)** | Non-zero `uvarint` / `uint32` allocated monotonically | Open, sparse, mutable or view-filtered collection where entities spawn, despawn, move between owners/containers or enter/leave a viewer's potential visibility | **Unified items** (`ItemId` across ground `id`, carried `instanceId`, `lineageId`, body `itemId`, reload `instanceId`), **authored/dynamic props** (`PropId`), **physics bodies** (`BodyId`), **tethers / hook flights** (`TetherId`), **projectiles**, **effects**, **traps** |
| **3. Retained string identifier** | Bounded UTF-8 string | External, display or map-authoring metadata not joined in hot tick/wire paths | **Player callsigns (`name`)**, **content/rules/profile IDs** (`content-7`, `PHYSICS_VERSION`), **room/resume tokens**, **authored map landmarks** (`station`, `charger`, `buildingId`, `nodeId`) |

### Why implicit indices stop at closed collections

Implicit positional indices must **never** be used as wire or cross-tick identities for
`items`, `bodies`, `projectiles`, `effects`, `traps` or `tethers`:

- **Per-view filtering:** `playerView` filters items, bodies and projectiles by
  potential visibility (`couldSee`, `inRange` in `shared/simulation/visibility.ts`). Array
  positions differ between the server, contestant A, contestant B and the directed view.
- **Insertion and removal:** Ground pickups, drops and body spawns mutate collections,
  and `shared/keyed-list.ts` (`rebuildKeyed`) relies on stable entity keys across layer
  deltas.

Conversely, `game.players` (fixed roster for a match, `<= 27`) and `map.gates` (fixed
immutable geometry for a match, pinned in `shared/simulation/game.ts`) never insert,
remove or reorder mid-match. Indexing them implicitly by `0 .. N-1` removes string
identifiers from every hot simulation and projection path.

## Entity & relation design

### 1. Players and seat roster (`PlayerIdx`)

- **Dense seat index:** A match assigns each roster slot an immutable `PlayerIdx`
  (`Brand<number, 'PlayerIdx'>`, `0 .. R-1`, `R = game.players.length <= 27`), matching
  `game.players[playerIdx]`.
- **Seat metadata updates:** `joinGame` (`shared/simulation/state.ts`) and post-start
  takeovers (`server/room.js`) update a seat's metadata (`name`, `role`, `kit`, `bot`)
  in place without changing `playerIdx`. Historical attribution on events is preserved by
  recording event-time participant snapshots on the event itself (see *Structured
  localized events*) rather than maintaining a separate append-only `occupants` table.
- **Static roster table vs per-tick state (`24.3` Proposals 3 & 7):**
  - Static/rarely changing seat metadata (`name`, `role`, `kit`, `seat`) moves to
    `welcome`/`ready` and seat-update messages instead of repeating on every player record
    every tick.
  - Per-tick `state` separates the viewer's own record (`self`, `24.3` Proposal 7) from
    observed records (`players`), and identifies any observed player by `playerIdx`.
- **Lookup alignment:** `tick.ts`, `rewind.ts`, `hook.ts`, `physics-presentation.ts` and
  `match.js` index `game.players[playerIdx]` directly (`O(1)`) instead of repeated
  `players.find(p => p.id === id)` scans.

### 2. Unified item identity (`itemId`) and separate scatter phase (`scatterSerial`)

- **Today's split:** Map generation emits `item-<n>` strings while `allocateItemId`
  (`shared/item-instances.ts`) emits `instance-<n>` strings from `s.itemSerial`, forcing
  `initializeItemInstances` to parse `/^instance-(\d+)$/` and `ground-items.ts` to
  coerce `String(item.id)` across `indexes` and `records`. Meanwhile, that same
  `s.itemSerial` counter also seeds `scatterPoint`'s `phase` (`angle = (phase + j) *
  2.39996`) in `seedAmmo` (`shared/simulation/ammo.ts`), `planDrop` and `planAmmoDrop`
  (`shared/simulation/loot.ts`), and is advanced by `allocateItemId` in `seedAmmo`,
  `ensureItemIdentity`, partial stack pickups (`collectInstanceEquipment` in
  `shared/equipment.ts`), and split stack drops — while remaining unchanged on
  zero-allocation drops (already-identified weapons) and discarded staged plans
  (`swapInstanceEquipment` in `shared/simulation/interactions.ts`, rejected `planDrop`/
  `planAmmoDrop`).
- **Target model:** Separate identity allocation from the legacy scatter phase schedule:
  - **Unified identity allocator (`s.itemSerial`):** One monotonic positive integer
    domain (`itemId >= 1`, `0` reserved). Map-placed items carry integer `1 .. M`
    (assigned at generation or normalized deterministically on map load; see
    [Compatibility boundaries](#compatibility-boundaries)), and `s.itemSerial` starts at
    `max(existing itemId) + 1` to allocate integer `itemId`s without string scanning.
    Ground `item.id`, carried `instanceId`, `lineageId`, `body.itemId` and
    `reload.instanceId` all share this integer type.
  - **Preserved scatter phase counter (`s.scatterSerial`):** Maintain `s.scatterSerial`
    exclusively as the drop-scatter `phase` counter, reproducing the legacy allocator's
    reservation and allocation schedule without coupling to `1 .. M` map IDs:
    - *Initialization:* `initializeItemInstances` starts `s.scatterSerial` at `0` (plus
      any pre-existing legacy carried-identity reservations) and advances it by `1` for
      each carried item missing an identity, ignoring map-placed item IDs.
    - *Every `scatterPoint` caller reads `scatterSerial`:* `seedAmmo` (`ammo.ts`),
      `planDrop` (`stagedScatterSerial + i` per copy `i`, `loot.ts`), and `planAmmoDrop`
      (`loot.ts`).
    - *Allocation-driven advancement:* `allocateItemId` advances `scatterSerial` by `1`
      alongside `itemSerial` whenever a new identity is actually allocated (`seedAmmo`,
      `ensureItemIdentity`, `collectInstanceEquipment` partial pickups, `planAmmoDrop`,
      and `planDrop` for `i >= 1` or unidentified `i = 0`). Zero-allocation drops
      (already-identified weapons; the first copy of an already-identified stack) advance
      `scatterSerial` by `0` (or `N - 1` for an identified `N`-copy stack), and staged
      `pickupStage`/`DropPlan` failures leave `s.scatterSerial` unchanged.
    - `#1147` must verify this with a focused equivalence witness covering `seedAmmo`,
      carried-identity initialization, partial stack pickups, zero-allocation weapon
      drops, split stack drops and discarded staged plans.
    - *Compatibility debt note:* `s.scatterSerial` is explicit temporary compatibility
      debt preserving exact physics drop geometry against `behavior-physics-1.v8.gz`.
      Replacing allocation-driven scatter with an independent owned placement sequence
      remains possible future gameplay work if drop geometry is deliberately changed, and
      is not an automatic follow-up.
- **Lookup alignment:** `ground-items.ts` indexes `Map<ItemId, number>` (`indexes`) and
  `Map<ItemId, GroundItem>` (`records`) directly without `String()` allocation.

### 3. Physics bodies, tethers and typed domain identifiers

- **Branded domain types (`23-types.md`, `shared/types.ts`):**
  - Define zero-cost branded numeric types `PlayerIdx`, `GateIdx`, `ItemId`, `PropId`,
    `BodyId`, and `TetherId` using `Brand<number, ...>` (`shared/types.ts`) so distinct
    relation domains cannot be mixed across callers or lookups. Do not bit-pack composite
    keys (no `(ownerKind << 29) | ownerId`).
- **Primitive `BodyId` + discriminated `owner` union:**
  - Today `PhysicsBodyView` carries a string `id` (`'actor:c0'`, `'item:item-42'`,
    `'prop:crate'`), `kind`, and redundant `actorId` or `itemId` (`24.3` shows `body.id`
    was derivable in 100% of frames).
  - Keep a primitive numeric key `id: BodyId` on every projected body record so
    `shared/frame-layers.ts` (`rebuildKeyed`), `shared/recording-format.ts` (`recordKey`),
    and delta indexing continue keying on one primitive ID without composite-key
    machinery.
  - Pair `id: BodyId` with a structured discriminated `owner` union identifying what the
    body belongs to:
    `{ kind: 'actor'; playerIdx: PlayerIdx } | { kind: 'item'; itemId: ItemId } | { kind: 'prop'; propId: PropId }`.
  - **Allocation and lifecycle of `BodyId`:** Allocate `BodyId` from a match-scoped
    monotonic counter at the simulation/presentation boundary (before per-view filtering
    so every authorized viewer sees the same `BodyId` for a physical body) — completely
    independent of `s.serial`, Rapier body handles, and `generation`. A `BodyId` stays
    unchanged across teleports and across visibility exit/re-entry for the same active
    body; only genuine body removal followed by re-admission/respawn allocates a fresh
    `BodyId`. Leave `PhysicsWorld` internal deterministic sort and tie-break keys untouched.
  - **Typed consumer lookups:** Client `arena-scene.js` and `physics-prediction.js` index
    the active body table by `BodyId` and maintain direct typed owner maps (`byActor`
    indexed by `PlayerIdx`, `byItem` keyed by `ItemId`, `byProp` keyed by `PropId`) with
    zero string concatenation or bit-packing.
- **Tethers and hook flights:**
  - `hook.ts` stores `casterIdx: PlayerIdx` and `targetIdx?: PlayerIdx` (instead of
    string `caster`/`target` with `s.players.find`), and projects active tethers with
    `id: TetherId` plus `a: BodyId` and `b: BodyId` endpoints instead of `'hook:' + p.id`
    and `'actor:' + id` strings (omitting the tether unless both endpoint bodies are
    authorized in the viewer's filtered `bodies` set). `hookFlights` carry `id: TetherId`
    and `casterIdx: PlayerIdx`.
- **One pose per entity (`24.3` Proposal 11):**
  - Actors with an active body and physical ground items carry `x`/`y` only on their body
    record; `self`, observed `players` and `items` omit duplicate `x`/`y` while a body
    is present. Eliminated/bodyless players keep `x`/`y` on their player record.

### 4. Closed enum tables (`24.3` Proposal 5)

- Define explicit frozen ordered arrays in the owning `shared/` modules for every closed
  union (`ROLES`, `KITS`, `WEAPONS`, `PHASES`, `AMMO_FAMILIES`, `ITEM_KINDS`,
  `BODY_KINDS`, `SHAPE_KINDS`, `EFFECT_KINDS`, `TRAP_KINDS`, `EVENT_KINDS`).
- Never depend on object key insertion order (today's `weapon` index implicitly tracks
  `Object.keys(content.weapons)`). Content and projection boundaries validate against
  the declared index table.

## Static geometry split (`24.3` Proposal 9)

### Gates (`gateIdx`)

- **Map delivery (`welcome` / `ready`):** `map.gates` is ordered once (`0 .. G-1`) and
  carries static geometry (`gateIdx`, `x`, `y`, `w`, `h`, `buildingId`, plus initial
  `open`, `locked`).
- **Live `state.gates`:** Carries only dynamic state indexed by `gateIdx` — either
  compact `(gateIdx, open, locked)` change entries in `frame-layers` or bit-packed
  arrays for `open`/`locked` over `0 .. G-1`. Static fields (`x`, `y`, `w`, `h`,
  `buildingId`, constant `kind: 'door'`) leave per-tick state and keyframes entirely
  (saving 787 repeated static descriptors per keyframe at `36x18`).
- **Engine alignment:** `PhysicsRuntime.gateOrder` (`shared/simulation/game.ts`) uses the
  canonical `0 .. G-1` order directly instead of sorting by string `a.id < b.id`.
- **Client merge:** `public/client.js`, `public/arena-scene.js`,
  `public/physics-prediction.js` and `public/replay-controller.js` update `open`/`locked`
  on the retained `arenaMap.gates[gateIdx]` entries rather than replacing
  `arenaMap.gates = state.gates`.

### Body shapes (baseline compression)

- A body's `shape` (`circle`, `box`, `convex`) is immutable for the lifetime of its
  `(id, generation)` (`shared/physics/world.ts`; `public/physics-prediction.js` already
  keys `identity` on generation + shape).
- **Why view-history alone is insufficient:** `shared/frame-layers.ts` diffs `set` against
  an immutable keyframe `all` (which late-joining or skipped-frame clients receive as
  `all` + current `set`, `server/room-views.js`), and [24.2](24.2-lossy-transport-deltas.md)
  datagrams diff against the client's acknowledged baseline `B`. Omitting `shape` after
  an earlier non-keyframe frame would break any client whose keyframe or acknowledged
  baseline predated that body's `(id, generation)`.
- **Wire/layer rule:** Treat `shape` omission as baseline compression, not unconditional
  send-once: every keyframe `all` carries `shape` for every body in that keyframe, and a
  `set` entry in a delta may omit `shape` **if and only if the target baseline** (keyframe
  `k`'s `all` in `frame-layers.ts`, or acknowledged frame `B` in `24.2` datagrams)
  **already contains that exact `(id, generation)`**. Any body newly spawned or
  regenerated since that baseline carries `shape` in `set` until the next keyframe (or
  acknowledged baseline) absorbs it, and the client retains `shape` from its active
  baseline for matching `(id, generation)` entries.
- **No welcome shape dictionary in `#1147` (`24.3` Proposal 9 deferred):** Do not add a
  welcome `shapeIdx` dictionary in `#1147`. Revisit `shapeIdx` only if future
  post-`#1147` wire measurements show body shapes warrant a separate table.

## Structured localized events (`24.3` Proposal 5)

Today `event(s, text: string)` (`shared/simulation/loot.ts`) formats English sentences at
five call sites (`shared/simulation/interactions.ts`, `shared/simulation/lifecycle.ts`)
and `public/hud-controller.js` reads `e.text`.

### Structured `GameEvent` model

Replace `text` on new events with a discriminated union keyed by `kind`, capturing
event-time participant snapshots (`EventParticipant = { playerIdx: PlayerIdx, name: string }`):

| `kind` | Payload fields | Replaces |
| --- | --- | --- |
| `'pod_powered'` | `actor: EventParticipant`, `slotsRemaining: number` | `interactions.ts`: `<name> powered an escape pod. <n> slots remain` |
| `'cell_charged'` | `actor: EventParticipant` | `interactions.ts`: `<name> charged a power cell` |
| `'eliminated'` | `target: EventParticipant`, `source?: EventParticipant` | `lifecycle.ts`: `<target> eliminated by <source>` / `lost to the arena` |
| `'respawned'` | `actor: EventParticipant` | `lifecycle.ts`: `<name> returned to the hunt` |
| `'match_finished'` | *(none)* | `lifecycle.ts`: `Broadcast complete` |

Each record retains `{ id: Serial, tick: Tick, kind, ... }`. On every participant snapshot,
`name` is the authoritative event-time display value and `playerIdx` is the seat
association only — formatters must render `participant.name` and never look up the
seat's current name to overwrite it, so mid-match joins or bot takeovers never rewrite
earlier event attribution during live play, delayed spectation or arbitrary replay seek.

### Lookup and localization utilities

- Add a pure shared formatter module (for example `shared/localization.ts` or
  `shared/events.ts`) exporting:
  - `DEFAULT_LOCALE = 'en'` (defaulted and assumed whenever no locale is passed);
  - a typed message-template lookup table per locale (`en` initially) and `kind`,
    separating formatting strings from simulation logic;
  - `formatEvent(event, locale = DEFAULT_LOCALE): string` — interpolates
    `EventParticipant.name` directly from the event payload (falling back gracefully to a
    safe placeholder if missing) and formats the template;
  - legacy recording compatibility: if an event carries `text` without `kind` (recordings
    below schema 20), return `event.text`.
- **Consumers:** `public/hud-controller.js` calls `formatEvent` on `state.events` for both
  live play and replay playback.

## Compatibility boundaries

### 1. `PhysicsWorld` determinism & `tests/fixtures/behavior-physics-1.v8.gz`

- `shared/physics/world.ts` sorts bodies and contacts lexicographically by `id`
  (`order(a, b)`), and `shared/simulation/ground-items.ts` (`unadmittedItems`) sorts
  pending item admissions by `item.id`.
- Changing internal `PhysicsWorld` body IDs (`'actor:c0'` -> numeric or zero-padded keys,
  `'item:item-10'` vs `'item:item-2'`) can alter admission/contact tie-break ordering,
  and **changing `snapshot` / `playerView` shapes directly changes the SHA-256 digests in
  `tests/fixtures/behavior-physics-1.v8.gz`** (`tests/characterization-physics-scenarios.js`
  hashes `JSON.stringify(frame)` and `JSON.stringify(playerView(...))`).
- **Implementation rule (#1147):** Never regenerate `behavior-physics-1.v8.gz` silently
  (`AGENTS.md`). Split `#1147` into two checkpoints so relational equivalence is verified
  separately from intentional wire/projection changes under [31](31-verification.md):

### 2. Wire versioning & recordings (`shared/protocol.ts`, `shared/recording.ts`, `26-recording-contract.md`)

- **Live wire (`shared/protocol.ts`):** Because `#1147` Checkpoint 2 changes live
  `state`/`welcome`/`ready` shapes (`self` split, relational IDs/indices, `id: BodyId` +
  `owner` union, `TetherId` endpoints, dynamic-only `state.gates`, baseline-relative
  `body.shape`, structured `events`), Checkpoint 2 bumps `WIRE_VERSION` (`3` → `4`) once
  when those wire changes land. `#1131` then bumps `WIRE_VERSION` again when adopting the
  selected outbound binary codec and closing remaining schema proposals.
- **Recordings (`shared/recording.ts`):**
  - Bump **both** `SCHEMA` (`19` → `20`) **and** `minimumReaderForMatch()` (`17` → `20`,
    `RELATIONAL_SCHEMA = 20`) on the writer side in Checkpoint 2. Because schema-19 readers
    cannot draw dynamic-only `gates`, `owner`-typed body refs, `self` split or `{ kind }`
    events without `text`, new recordings must declare `minSchema: 20` so `recordingFit`
    refuses them on pre-20 builds as `'too-new'`.
  - Keep `MIN_SCHEMA = 10` on the **reader side**: `public/replay-controller.js`,
    `public/hud-controller.js` and `public/arena-scene.js` continue playing schema
    `10..19` archives by reading legacy `{ text }` events when `event.kind` is absent and
    normalizing legacy `player.id` / `gate` / `body` records against `header.map`.

### 3. Map generation artifacts (`docs/53`, `tests/fixtures/room-arena-9.v8.gz`)

- Map generation (`map/live.ts`, `map/micro/`, `map/macro/`) currently outputs `item-<n>`
  and `door-<n>` strings.
- **Recommended boundary:** Keep map generation's saved artifact schema untouched in
  `#1147` by assigning dense `GateIdx` (`0 .. G-1`) and unified integer `ItemId`s
  deterministically at match/payload initialization (`createGame` / `prepareMapPayload`)
  when loading `map.items` and `map.gates`. That avoids an unrelated 224-map chain-sweep
  or `room-arena-9.v8.gz` recapture; migrating mapgen's own artifact format can remain a
  separate `docs/53` step if desired later.
