# 51.10. Measurement (stage 8)

Up: [51](51-generation-chain.md). Shared invariants and vocabulary: [51.1](51.1-principles-and-names.md).

### 8. Measurement: BuiltMap, proof, Layout → **Report** (view)

- **Core elements, counted per set piece instance.** This is the first point at
  which a set piece class's promise can be checked (see [51.11](51.11-core-elements-and-playground.md)). It works
  on core element *sites*, not regions:
  1. **Assign each site.** A site is assigned to the set piece instance whose
     slots contain the cell it stands in. Instances never share a slot, so the
     assignment is unique.
  2. **No stray sites.** A site that falls in no instance's slots, or in an
     instance whose class doesn't own that core element, is reported as a defect.
  3. **Exact counts.** Each instance of a class that owns core elements must have
     exactly the promised count of each core element among its assigned sites:
     `contestantCount` spawns for `start`, `exitCount` exits and `hunterCount`
     hunter spawns for `end`, one
     charger for `charger`.

  Two adjacent instances whose core element regions merged are caught this way.
  The one strategy sites one set of core elements, so they all land in one
  instance's slots and the other instance counts zero. The strategy never
  needs to know about instances.
- **Reachability, by inference** (principle 8, 17 M6). The map is reachable
  when every link holds:
  - the proof connects every layout region to the spawn's (stage 4)
  - every builder kept its promise (stage 6)

  No whole-map flood decides anything. The game's diagnostic checks each
  region's portal promise on its own geometry (`diagnoseBuiltMap`), to help
  find a defective builder.
- **The report diagnoses; it doesn't reject.** A failure here names a defect,
  either an authoring defect or a builder that broke its contract. It is not
  an invalid map to discard. Tests, batches and the sweep use the report to
  find defects.
- **Metrics:** measured from the built map, not from a tile graph.
- **Navigation structure** (#688): the deterministic, read-only
  `navigation-structure-1` report in `map/tools/navigation-structure.ts`, run with
  `node map/tools/cli.mts navigation MAP.json --out REPORT.json` (BSON also works).
  Corey's direction is recorded in [17.2.11](17.2.11-navigation-structure-direction.md)
  and [54](54-region-types.md#navigation-structure). Definitions follow below;
  the first three-size evidence is in [42.23](42.23-navigation-structure.md).
  These are comparison measures, not targets, admission rules or content tuning.

## Navigation structure definitions

Every distance is in world units and every area in squared world units. The tool
reads the complete built results, uses the saved cell size, translates through
`builtMapFrame`, and emits both contestant and hunter (`gladiator` internally).
Doors are openable, as in the navigation planner: unlocked doors do not block.
It uses the existing body-specific eroded free-space triangulation and funnel
search ([22.6.1](22.6.1-portal-graph-and-mesh.md)); it does not simulate discovery,
door-opening time, dynamic bodies, combat, or players choosing routes.

**Detour.** Route length divided by Euclidean endpoint distance. The whole-map
mesh uses the same navigation geometry implementation with the full playable
domain, avoiding stretch introduced by representative portal crossings. Within
one region, searches use navigation's region domain and its 96-unit margin;
these paths may use that margin but cannot take an arbitrary excursion across
the map. Each returned segment is swept against exact collision geometry at
navigation clearance, with the existing collision-radius rule for endpoint
connectors. Paths are mesh-search witnesses, not certified globally shortest
geodesics. A ratio can therefore include mesh corridor selection overhead.

Gameplay routes come first: every contestant and hunter spawn to every exit
and charger, followed by every charger to a deterministic systematic loot
sample. Loot is in composed region/result order, retaining index multiples of
`max(1, ceil(lootCount/32))`, at most 32 targets shared by both bodies. These are
built candidate loot sites, not randomized live pickup contents.

Point-pair endpoints are owned cell centres inside each body's mesh. Per region,
the 16 lowest fixed multiplicative-hash ranks of cell indices are retained;
the same ranking selects at most 96 centres across the map (using original
concatenated cell indices). Original indices are assigned before walkability
filtering. Rank distinct selected pairs by the same fixed hash of
`i * selectedPointCount + j`, where `i < j`, taking at most three pairs per region per distance
stratum and 24 across-map pairs per stratum, with across-map endpoints in
different regions. Strata are **short <6 cells**, **medium 6–<24 cells**, and
**long >=24 cells**, using straight distance. A stratum with no eligible pair
is absent, not an observed zero. Small regions may have fewer pairs. Endpoint
sets differ by body; gameplay targets do not. This bounded geometric sample is
not uniform sampling of area or player traffic.

Each category/stratum reports nearest-rank median and p90, and the share strictly
above 1.5, over successful positive-distance pairs only. Zero-distance pairs are
excluded. Attempted counts and invalid endpoints, disconnected mesh components
in the searched domain (`unreachable`), unresolved `search-miss` and rejected `sweep-defect` counts are
separate; a miss is not proof of a broken generation promise. Raw endpoints,
statuses and lengths remain in the report. Region-type and portal-count route
breakdowns separately attribute routes to their **origin** and **destination**
regions, not to every region they cross. Within-region categories directly
describe that region's local geometry.

**Dead-end area.** A deterministic geometric proxy for a substantial single-mouth
pocket, measured over the whole-map eroded triangle adjacency graph. Find graph
bridges. Cutting a bridge leaves two sides in its connected component; choose
the smaller-area side (DFS child on an equal-area tie). Its opening is the shared
mesh edge. Qualify only edges with eroded width between **0.5 and 2 cells**,
inclusive, side area at least **4 square cells and twice opening-width squared**,
and maximum distance from opening midpoint to a side triangle's centroid at
least **twice opening width**. The minimum width excludes tiny prop gaps; the
area/depth and maximum width exclude arbitrary small leaf triangles and broad
room diagonals. Union all qualifying smaller sides, counting nested cuts once.
Report the cuts and disconnected-component count as well as union area.

This is configuration-space area for each body, not floor area. It identifies
backtracking opportunities, not actual exploration or forced player decisions.
It deliberately omits very narrow mouths, wide-mouth bays, and pockets whose
mesh dual graph has cycles across the mouth. It can count a terminal corridor
without a widened room. Triangulation and thresholds affect the result; compare
the same definition and retain its version. For type/portal-count attribution,
clip every triangle at ownership-cell boundaries and sum its intersection area
for each owner. Long triangles can span several regions; centroid attribution
would distort those breakdowns.

**Empty space.** Sample four quarter-cell centres per owned cell. A sample is
walkable if it lies in the body's eroded mesh. It is empty if its Euclidean
distance to every physical structure footprint is **greater than half a cell**.
Footprints are obstacle shapes, gate rectangles, enclosed-building rectangles
and actual roof cells, translated into world coordinates. Roof overhang and
decals are excluded. Reserve rectangles, addressed claims and loot sites are
excluded. An intentionally empty court still counts unless actual structure
is nearby; a roofed/enclosed interior is a structure, not empty outdoor ground.
Empty area estimate is empty sample count times cell area /4; empty share uses
walkable samples as denominator. This is a fixed-resolution estimate, which
can miss subcell features, kept separate from detour and exact mesh area.

**Macro structure.** Count each region's declared external portals and the
fraction of regions with exactly one. Count all exposed owned-cell sides,
including map/void edges, for perimeter. Portal run length divided by perimeter
is the guaranteed-passable boundary fraction; its complement is explicitly
`nonGuaranteedBoundaryShare`, since absence of a promise is not a physical wall.
Measure physical impassability separately: sample two quarter points per exposed
cell side, sweeping perpendicular from a quarter-cell inside to a quarter-cell
outside at body clearance. Report failed sweeps / boundary samples. This includes
map edges and local approach obstruction; it is an estimate of actual crossing
availability, not an exact union of blocked boundary intervals. Internal region
interfaces appear once for each owner. Per-region rows and type/portal-count
groups retain denominators, so area-weighted or boundary-weighted comparisons
need not average incompatible percentages.
