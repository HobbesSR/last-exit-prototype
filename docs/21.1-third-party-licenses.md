# 21.1. Third-party licences and notices

Status: audit of 2026-10-26 (#551) against `forgejo/main` 872932e. Child of [21](21-stack.md).
The project licence decision is [17.4](17.4-live-service.md) #11 (#552).

`LICENSE` (MIT) covers the project's original work only. Third-party material keeps its own
licence. This document records what the project redistributes, the evidence for each licence,
how each obligation is met, what remains unresolved, and how to keep it current.

## Delivery

The repository contains no third-party package code: `node_modules/` is installed from the two
lockfiles and never committed. Third-party code reaches other people only when the server sends it
to a browser. That happens by two routes, both declared in `server/shared-assets.js`:

- `VENDOR_DIRECTORIES`: package directories served as installed (`/vendor/phaser`, `/vendor/lucide`,
  `/vendor/sat`, `/vendor/rapier`). Every client receives these.
- `VENDOR_MODULES`: CommonJS/UMD packages wrapped as ES modules by `server/vendor-modules.js`,
  including every file their `require()` calls reach. Served only when developer tools are on.

`THIRD-PARTY-NOTICES.txt`, generated from `tools/third-party/components.json` by
`npm run notices`, holds every licence text and notice for both routes. The server serves it at
`/third-party-notices.txt` under every dev-tools policy; the deploy dialog and the dev-tool
navigation link to it. Each wrapped module starts with a `/*! ... */` banner naming the packages,
versions and licences it bundles and that URL. The wrapper does not remove comments, so notices in
the sources survive (Clipper's header, SAT's header). The statically served minified files are
unmodified, so a notice stripped by an upstream build (Phaser, Rapier, Delaunator, Constrainautor)
is restored by the notices file, not by the bundle.

The project's own `shared/` modules are served to browsers as source with types stripped; comments,
including the fdlibm notice in `shared/math.ts`, are kept.

Not redistributed, so no notice obligation arises from this project's current delivery:

- Server-only runtime packages (Express and its dependency tree, `ws`: MIT, ISC, BSD-3-Clause for
  `qs`). They run on the host and are not sent to clients. A deployment artefact that bundles
  `node_modules` (for example a container image) would redistribute them and need their notices.
- Development-only packages in either lockfile (TypeScript and its platform binaries, Playwright,
  `@types/*`, Prettier, `undici-types`): Apache-2.0 or MIT, used locally and in CI.
- Inter and Segoe UI are named in CSS but no font file is shipped; the browser uses an installed copy.

## Obligations and how they are met

- MIT, ISC, BSD-2-Clause, the phrogz licence and Boost: keep the copyright notice and licence text
  with copies. Met by the notices file and, where the upstream file keeps it, the file's header.
  Boost requires the text with source copies, which these are.
- Apache-2.0 (Rapier, the Rust crates, the AudioContext polyfill): give recipients a copy of the
  licence and keep attribution and any NOTICE file. Met by the notices file; there is no NOTICE.
  The project does not modify these files, so no change notices are due.
- PSF (heap.js): keep the PSF agreement and its copyright notice. The notices file carries the
  agreement as the package distributes it. The summary of changes the agreement asks of derivative
  works is the porter's; the project distributes the port unmodified.
- fdlibm: keep the notice. Kept in `shared/math.ts` and repeated in the notices file.
- None of these licences requires an in-game credit, a source offer or copyleft compliance. No
  GPL, LGPL, MPL or other copyleft component is redistributed.

## Unresolved

The audit does not establish blanket compliance for these; each needs the action named before it is claimed.

1. **Rapier's full crate tree.** The crate list comes from source paths left in the WebAssembly.
   A crate that leaves no path (for example `rapier2d` itself, `wasm-bindgen`, `simba`,
   `num-traits`, `bitflags`) is not enumerated. The dimforge crates and the Rust ecosystem's
   usual crates are Apache-2.0 or MIT OR Apache-2.0, so the Apache text very probably covers
   them, but that is unverified. Resolving it needs `cargo about` (or equivalent) run on the
   rapier.js source at the published commit; npm records `gitHead` b716d375efc0201003f0cd9ef7168eee0b62c177,
   and the repository has no tag for 0.21.0.
2. **heap.js licence.** The published 0.2.5 says PSF; the upstream repository changed its LICENSE to
   MIT on 2021-12-02 without a release. The project follows the published PSF terms. Whether the
   PSF terms still bind the port is the upstream author's and PSF's question, not this project's.
3. **Header-less copies inside Phaser.** Embedded components were found by their source headers.
   A snippet Phaser copied without attribution would not be found. Phaser's own MIT notice is the
   only evidence for the rest of its source.
4. **Original SVG authorship.** The three SVGs carry no record of how they were made. The
   repository owner should confirm they are original (or record their source) before #552's MIT
   claim is taken to cover them.

## Updating

When a dependency is added, removed or upgraded, or the server starts serving a new package:

1. Run `npm test`. `tests/third-party-notices.test.js` fails when a served package is missing from
   `tools/third-party/components.json`, when its installed or locked version differs from the
   audited one, or when the committed notices file is stale.
2. For each change, read the package's actual LICENSE/NOTICE files and its served bundle's headers,
   and search its source for embedded third-party code. Record the licence texts: package files by
   their `node_modules/` path, anything else as a file under `tools/third-party/texts/` taken from
   the authoritative upstream text. Never paraphrase a licence.
3. Update the entry's version, embeds and texts, run `npm run notices`, and update the tables above.
4. A new route that serves third-party files belongs in `VENDOR_DIRECTORIES` or `VENDOR_MODULES`,
   where the test sees it. A copyleft or unclear licence is a decision for the repository owner,
   recorded in 17.4, not something to add quietly.

The test covers packages and versions, not licence content: a new licence inside an existing
version, or a newly embedded component, still needs this review.
