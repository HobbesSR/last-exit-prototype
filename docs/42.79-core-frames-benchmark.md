# 42.79. Frames from the core's output benchmark (#1344)

Up: [42](42-performance-history.md). Design: [27.2](27.2-tick-architecture.md#frames-3d3). Earlier points:
[42.76](42.76-state-flip-benchmark.md) (end of the state flip) and [42.78](42.78-tick-cutover-benchmark.md) (the tick
cutover).

## Paired tick and frame

The change builds each frame from the core's completed ticks in a frame store instead of cloning the `Game` mirror. The
simulation is unchanged ([continuity](reports/issue-1344/frame-continuity.md)), so both sides tick the same match and the
pair isolates the frame path. The store folds each tick's change list as the step decodes it, so its cost appears under
`sim.step`. The frame's cost is under `sim.snapshot`.

| Median of five round means, ms/tick | `main` (`08fb0e4d`) | This change |
| --- | ---: | ---: |
| No traps: tick + frame | 1.927 | 1.949 |
| No traps: step | 1.685 | 1.715 |
| No traps: frame | 0.232 | 0.188 |
| Traps: tick + frame | 2.056 | 1.689 |
| Traps: step | 1.485 | 1.491 |
| Traps: frame | 0.569 | 0.194 |

The frame got cheaper. The old one structured-cloned the mirror's players, traps, projectiles, effects and events every
tick, and with a trap on the map that clone was most of the frame's cost. The new one writes each record from the core's
last record and shares unchanged lists. The fold adds about 0.03 ms to the step, and the step also still includes the mirror's
own apply until #1284 removes the mirror. Without traps the pair is within the rounds' spread: tick plus frame ranged over
1.84–1.97 ms across the change's rounds and 1.88–2.07 across the baseline's. With traps it is 18% lower. Both sides averaged 7.64 active contestants and
813 ground records without traps, and 7.11 and 813 with them.

Against the earlier points, tick plus frame on this map was 5.831 ms at the end of the flip (42.76) and 2.886 at the
cutover (42.78), or 6.242 and 3.042 with traps. Those pairs ran different rules and bot traces, so they place this
change on the series rather than measure it.

## Method and limits

Windows, Node 24.15.0, release WASM. The baseline is `git archive 08fb0e4d` with the same core, since the change
touches no Rust. The map cache was generated by the baseline's run; it is the 24×12 cache, seed 4217, SHA-256
`b13d673b8b5fc101dca36b2b2d27cbc9d15c525a281a902d0b9f5b7a95c37ebe`, the hash 42.78 recorded. Each run is five
rounds of 300 warm and 600 timed ticks, each tick with a private frame (`snapshot`, which also queries the bots'
routes). Runs were ordered baseline, change, change with traps, baseline with traps. Outside load was 5.5–7.2% of the
machine, below the 25% threshold. One pair per trap setting does not characterize run-to-run spread, and the result is
one map and its bot trace. Projection (`playerView`) is outside the timer. Its item grid is now the frame store's ground
list rather than the game's, with the same incremental index.

Reproduce from the repository root with `node tests/bench-phase-three.mjs --root=<08fb0e4d-archive> --cache=<cache>`
and `node tests/bench-phase-three.mjs --cache=<cache>`, each again with `--traps`. Junction `node_modules` into the
archive and copy its `shared/core-wasm.generated.ts` from a built tree, or build its core. [Raw rounds and
contention](reports/issue-1344/benchmark.json).
