# 42.64. Phase 4's glue in the Rust core: floor drag and the pose write-back (#1226)

Up: [42](42-performance-history.md). Design: [27](27-rust-path.md#the-state-flip), step 5a. Floor drag is
`rust/core/src/floor_drag.rs`, run by the world (`physics.rs`, `apply_floor_drag`) over its own props. The write-back
reads the step's paths. `characterization-physics`, its `-bots` variant and `tests/tick-phases.test.js` passed
unchanged.

## Finding

**Both parts got cheaper, so 42.58's budget is met with room to spare.** Together they save about 13 µs a tick, about 0.5% of the 2.8 ms mean tick on this map (42.58). No crossing is added: floor drag is one call
that returns only the changes, and the write-back reads output the step already returned.

| Per tick, 24x12, seed 4217, after 300 ticks (80 dynamic bodies, 69 of them items, 11 actors) | TypeScript | Core |
| --- | ---: | ---: |
| Floor drag (`applyFloorDrag`) | 7.18–7.56 µs | 0.48 µs |
| Item and actor pose write-back | 15.0–15.3 µs | 8.71–8.83 µs |

- **Floor drag was a full world snapshot each tick.** The TypeScript built a record and read a pose for every dynamic
  body, then made one `setDamping` call per prop. The core walks its list of props (at most 128) and returns only the
  dampings that changed, which is none on a quiet tick.
- **The list matters.** The first version walked every slot, and this map has 14,412 static colliders. That cost
  about 30 µs, four times the TypeScript. Keeping the props' slots in their own list is what made it cheap.
- **The write-back** still writes JavaScript's records, which it owns until #1214. It now reads the pose from the end
  of each body's path rather than making one `getTransform` call per body.
- **The contact drain** is not timed. The tick now builds no contact records, and on a quiet tick it had none to build.

## Method

- **Environment.** The development machine (Windows 11), Node 24.15, the core built with `npm run core:build`.
  2026-11-20, under the exclusive bench lock.
- **The script** was ad hoc, not committed: one game on a 24x12 live map, seed 4217, the shipped content, stepped
  300 ticks. Then 20,000 calls per variant, rotating which variant goes first, with 7 rounds after a warm-up.
  - The TypeScript variants were the retired code, copied into the script.
  - The write-back variants read one held set of paths.
  - A no-op baseline was 0.004–0.006 µs.
- **Three runs**, each reporting the per-variant median of its rounds.

## Limits

- **Node only.** The browser does not run the tick.
- **No damping changed** in the timed calls, since the state was held. A body that crosses a floor's edge adds one
  output row and one spec rewrite, as `setDamping` did before.
- **The step itself was not timed** (42.61 has it). This change does not alter what it simulates.
