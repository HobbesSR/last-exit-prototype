## Experimental dynamic overlay (#448)

`content-physics-8` adds `simulation/dynamic-navigation.ts` after waypoint and
threat selection, before motor construction. It queries only currently visible
actors (`visibleTo`) and nearby solid prop poses (`visibility.visiblePoint`), with line of sight
and roof concealment; gladiators' full layout knowledge does not grant hidden
dynamic observations. Item goals keep using discovery's remembered item poses.
Loot sensors never enter the overlay, and sleeping props keep normal sight rules.

When the leading leg is blocked, a bounded local visibility graph uses expanded
body bounds as candidate corners and sweeps each edge against actual observed
shapes, authored static geometry and remembered doors. Contestant static sweeps
require the whole local segment support to be surveyed; unseen door state is
optimistically open. Up to eight nearest shapes supply corners, but all observed
shapes reject unsafe edges. Physical movement uses the narrower pinned P2 radius;
global navigation retains authored clearance and portal guarantees.

The overlay retains only its own route in a private WeakMap, checks its next leg
against current observations each tick, drops it on a changed global route/goal
or displacement, and prefers the direct leg as soon as it clears. A new bounded
search is staggered by roster position, with the bounds pinned in
[14](14-match-rules.md). Rejoin extends beyond the observation horizon so a
blocker at that horizon does not contain the rejoin point. A failed, deferred or
budget-limited detour advances along the direct leg to the first observed actor's
clearance margin, using the bounded prefix search in [14](14-match-rules.md).
This creates a contact-range queue instead of a stop at observation range.
Props participate in detour planning but do not forbid a direct motor fallback:
P5's existing bounded pushing remains available through normal solver contact.
The overlay never sets a body pose or applies an extra push impulse. It does
not guarantee arbitrary long detours around a persistent crowd. Ordinary solver
contacts remain authoritative, with no teleport fallback.

The pre-movement intent collection shares one stable roster ordering and one
solid-prop pose query for the whole room. This cache exists only during that
collection and is discarded in `finally`; between-phase and between-tick reads
are fresh, including same-tick developer teleports. Sight and actor exceptions
stay owned by `simulation/visibility.ts`, with a shared geometric point predicate.

Corey's [17.3](17.3-product-gameplay.md) entry 24 defers strategic blockage
clearing. Keep the overlay advisory: observations identify present dynamic
geometry, local planning selects a motor destination, and only the motor/solver
changes physical state. Future tactics may build on those stages. A failed
attempt neither stamps a prop into static topology nor permanently declares
its goal unreachable, and later observations can reopen the direct leg.

Static topology is never rebuilt for moving/sleeping props. Authored obstacle
and mask geometry remains pinned. Gates retain their existing single mutable
state, occupancy refusal, native collider synchronization and observation-based
tile repair. This adds no general runtime scenery mutation/destruction API.
Bounds and experimental selection are [14](14-match-rules.md); evidence is
[42.19](42.19-physics-p8.md).
