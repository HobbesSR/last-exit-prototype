## Playtest and diagnostic scope

Run `npm run dev` and open `/dev/physics` on the server. The route and the three
direct lab filenames return 404 when the
developer-tools policy is `none`. With tools enabled this is a local browser
simulation, without a room connection or hidden live-room data. Policy `owner`
does not require a room credential for this isolated lab, just as for the map labs.

Scene A has four contestants and a 60-unit doorway for contact, slide and crowd
experiments. B adds a rotated solid crate. C provides a hook gladiator and target.
All use copied `content-physics-8`; reset pins tuning in a fresh world and disposes
the previous one. These scene names do not allocate new content identities.
The desktop workbench keeps the arena between scene/actor controls and a scrolling
tuning/recording inspector. Start/Reset, Step and Play stay in the action bar;
recording JSON and expandable diagnostic help stay in the inspector. Smaller
windows stack the panels with the arena first.
Click or tab to the arena to use keyboard controls. They are the live client's
([`input-controller.js`](../public/input-controller.js)): WASD or the arrow keys move the
selected actor, the pointer aims, Q queues one skill press and E one interact press. Both
are one-shot presses, as live. Space and Enter have no simulation meaning, so they keep
their native button behavior. The impulse control tests recovery: click or drag its circle to
set direction and strength (the rim is the Max impulse tuning), or type exact X and Y, and press
I on the arena, or the button, to queue it. The live game has no such key, so I is a lab key the live
client leaves free. Step advances one 50 ms tick; Play advances
fixed ticks on a timer without changing solver substeps. The speed selector (1×, ½×, ¼×) only stretches the timer
gap between those same ticks, so a recording is identical at any speed. Pale dots mark the selected actor's last
40 ticks, one per tick, and a readout under the status line gives its speed, motor target and peak speed over
that window, computed from retained positions, plus its skill cooldown. Together they show how fast an impulse
decays. The Hook cooldown tuning (default `content-physics-6`'s 140 ticks, 7.0 s) replaces `hook.cooldownTicks` and
the kit table's copy for that pinned match only; it changes no shipped content.
Focusing an editable field clears held movement; holding a
movement key while clicking Step remains supported. Editing fields and operating
buttons do not invoke simulation keyboard shortcuts. Attack, sneak and inventory keys
are not wired: the scenes have no weapons, sensors or loot for them to act on.
The arena keeps
its square world aspect ratio when resized.

The canvas distinguishes head/body/combat radii, sleeping bodies, tether anchors,
final-substep solver contact points/normals, motor velocity targets, requested
impulses, final-substep external forces and the hook tip segment between retained
frames. Cast ahead runs a read-only 200-unit disk sweep against current static
geometry, closed gates and rotated solid props using the shared swept-query
helpers. It excludes actors and sensor loot and draws its requested path and
stopped disk; the ordered diagnostic action reruns on import.
External force excludes motor velocity changes and collision impulses;
the hook-tip segment is not a general query-cast history. Diagnostic accessors
run only when called and do not add fields to gameplay captures or projections.

Export/Download JSON retains the map, seed, complete copied content, selected actor,
ordered input/impulse actions, captured frames, contacts and external forces under
`last-exit-physics-lab-1`. Import reruns the actions and compares every gameplay
frame exactly. This is diagnostic reproduction on the supported runtime, not an
exact backend checkpoint or a production replay. Recording stops at 2,400 ticks
or 4,800 actions. This is not a global simulation-query or contact-impulse history.

Human review should retain the exported configuration/trace and separately record
pass/fail, reviewer and observations for glancing slide, allowed visual overlap,
crowd squeeze, impulse recovery and hook fairness. None has human signoff yet.
Default activation needs that signoff plus a separate reviewed version/content
checkpoint. There is no live mid-match fallback or public deployment here.

## Measurement method and limits

`npm run physics:integration` runs legacy control and A/B/C workloads sequentially
under the machine benchmark lock. Each has 11 and 27 actors on sparse and clustered
17,280 by 8,640 open rectangular masks. A has actors only; B/C admit 128 total
dynamic bodies: actors, 64 solid crates and 53/37 loose sensor items. Alternating
small impulses keep non-actor bodies awake. C additionally admits eight bounded
ropes directly; this loads the constraint API rather than pretending eight hook
shots attached. Bots are disabled and damage is zero, so this is not a generated
map or whole autonomous room-capacity guarantee.

The report retains raw input/step/snapshot/projection/serialization/total samples,
raw/projected and gzip frame sizes, observed awake/sleeping counts, initialization,
disposal, heap/RSS observations, fixed engine settings and source/package/WASM
hashes. Two identical-action runs compare ordered gameplay-state hashes. Gzip and
byte counting occur outside timings. `step` includes the whole simulation, not
just the solver; `total` includes input preparation, snapshot, one projection and
two JSON serializations. Neither measures server scheduling or multiroom capacity.
Heap/RSS after disposal includes retained JS state and allocator/GC noise; it is
not a WASM memory-leak census.

The first attempt requested 101/117 authored crates and was rejected by the
existing 64-crate authoring guard. The corrected workload uses sensor items for
the remaining slots. The rejected input is evidence, not a reason to loosen a
limit. A report's timing success alone cannot qualify privacy, containment or feel.
