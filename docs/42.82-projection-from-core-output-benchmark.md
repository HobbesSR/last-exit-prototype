## Paired room loop, eleven viewers

`playerView` now reads only the frame and a view source: seats through `MatchIds` and knowledge from a cache beside the
frame store. The cache keeps only each contestant's discovered cells and each player's live cues. The pair runs
`tests/bench-stages.mjs --clients=11 --ticks=1500` (seed 4217, `content-12`, 12x6, recording on), alternating this change
with its base, #1361's head (`a8f27d34`), three times on 2026-11-26. No other work shared the machine.

| ms/tick, mean of 1500 ticks | Base, runs 2, 4, 6 | This change, runs 1, 3, 5 |
| --- | ---: | ---: |
| Tick | 2.55, 2.55, 2.57 | 2.55, 2.54, 2.52 |
| Tick p99 | 4.65, 4.82, 4.16 | 4.72, 5.40, 4.34 |
| Not under a stage timer (mostly the step) | 1.38, 1.38, 1.38 | 1.36, 1.36, 1.35 |
| `sim.playerView`, 11 views | 0.48, 0.49, 0.50 | 0.50, 0.49, 0.49 |
| `loop.encode` | 0.21, 0.21, 0.21 | 0.21, 0.21, 0.21 |
| `sim.tick.memory` | 0.05, 0.05, 0.05 | 0.02, 0.02, 0.02 |

- **Projection is unchanged.** It costs about 0.045 ms per view, and the view source adds nothing measurable. 42.81's
  0.13 ms was one view with its first-view costs.
- **Encoding is unchanged,** as expected: what reaches the wire is the same.
- **Memory refresh falls from 0.05 to 0.02 ms.** The cache keeps only the discovered cells, where the old writer rebuilt the
  bots' `SeenCells` and `ItemMemory` from every refreshed memory.
- **The untimed share falls by about 0.02 ms.** Cues are queried only for players who hold a live one or are named in the
  tick's heard facts, rather than for all eleven every tick.
- **The tick** is within the runs' spread, perhaps 0.02 ms lower. The p99s overlap.

The whole projection stays in TypeScript by #1352's D1. Moving it to Rust is #1357, triggered by readiness rather than
by these numbers.
