# 42.48. Wire codec backend comparison (#1130)

Up: [42](42-performance-history.md). Accepted direction: [24.1](24.1-wire-encoding-design.md).
This is the bounded comparison 24.1 asks for, before Corey chooses a backend. It
changes no live protocol, `WIRE_VERSION`, simulation, recording or fixture.

## Recommendation (for Corey's decision)

**Adopt the application-owned static descriptor codec (D) for #1131, with the limits below.**
Both D and msgpackr records with a provisioned table (M) met the byte and CPU budgets, so
neither was disqualified there. The selection rule prefers the maintained library only when
the two are within 15% on bytes and 25% on CPU. They are not. D's steady frames are 17–42%
smaller than M's in every view. M decodes 1.1–2.2× faster, but in absolute terms that is at
most about 6 µs per message in Chrome. Server encode is the cost that scales, per view per tick, and
there the two are equal.

D also has the concrete fits that the rule requires of custom code:
- **Exact semantics.** D matches the JSON round trip on every specimen. M keeps keys whose
  value is `undefined`, replaces lone surrogates with U+FFFD and drops a `__proto__` map key.
- **Capped packing.** D packs at record boundaries in one pass. For contestants, D fit the
  whole slice under the 1,200-byte cap in 56–59 of 61 messages; M fit it in 28–34.
- **In-codec quantization.** D quantizes inside the codec at no extra CPU. M needs an object
  transform that costs 1.1–2.3× JSON encode.

Limits of the recommendation:
- **Maintenance.** D is about 260 lines of codec and 83 of schema for this one slice. #1131
  must give every protocol record reviewed types: that is the real cost, and it is unmeasured.
- **Chrome decode allocation.** D misses this budget (2.3–3.4× JSON). Building records field
  by field grows property stores. Generated object literals might fix that; this study did
  not measure them.
- **No integrity check.** About 21% of random corruptions decode to a different valid-looking
  message. D relies on transport integrity, as JSON does.

M is a viable fallback if Corey prefers maintained code. It needs three boundary rules
outside the codec: projections must never emit `undefined` values (enforced by a test), lone
surrogates must be rejected where names enter, and map keys must stay closed. It also needs
an explicit nesting limit, or acceptance of stack overflow as the bound. It must be served
as its minified UMD build, with a 21.1 notice.

Neither candidate is a datagram protocol (24.1). Neither result settles #1094's precision
or baseline policy.

Budget 4b fails for both binary candidates in Chrome, so it does not discriminate between
them. Chrome's `JSON.parse` allocates notably less than Node's does here, where decode
includes `Buffer.toString`. Budget 6 is noisy. Each figure is one batch of variants, the
variants grow 0–15% in bytes as their baselines age, and JSON itself reads 0.84–1.29×. D read
0.92–1.16× and M 0.76–1.23× per variant, between N = 1, 4 and 16. No candidate shares state
between variants. The check cannot separate the candidates.

## Workload and provenance

Measured 2026-11-16 UTC (evening of 2026-11-15 local) on Windows with Node v24.15.0 and
Chrome 157.0.8103.51, on an AMD Ryzen 9 5900X. Branch `claudecode/1130-codec-selection` from
`9fe66ab`. The caches are 42.47's retained tuned `chain-live-2` caches: seed 4217, content-7,
source `5cdcd5c`. The driver checks that `map/`, `shared/` and `server/` are unchanged since
that source, except for this branch's declaration exports in `projection-contract.ts` and
`visibility.ts` (diff hash in the report; no behaviour change). Both final runs were sequential
under the exclusive lock and uncontended (external busy 5.1% and 6.5%). An earlier pair of runs
was discarded because the driver was edited while it ran. Source hashes (LF-normalized) are in
each report.

The four views and 1,200 ticks match 42.47. The real production `broadcast` built every payload,
and every delivery was rebuilt through the layer and discovery decoders and checked: 4,804 per
size. Every twentieth tick was sampled, giving 61 per view. The codecs encode the **raw**
projected object that `JSON.stringify` received, captured with `structuredClone`, so `undefined`
and -0 reach them as production would. Each output is compared with the JSON round trip of that
object. All 244 samples per size round-trip exactly through D, M and inline msgpackr, again on a
fresh decoder in shuffled order. M's provisioned table was unchanged afterwards.

**The slice** is the state envelope header (`version tick phase directed contestantsActive
physicsProfile`, plus the prediction fields) together with `players` and the `bodies` layer. It
is not a whole message. Items, gates and the other families are excluded, so the 36x18 and
12x6 slices are similar in size. Directed views carry at most 11 players and 80 bodies. The
specimens are `ping` and an `input` (input is measurement only).

**Field names** come from the projection owners. `OWN_FIELDS`, `ITEM_FIELDS` and `OBSERVED` are
now exported. Constructed fields (discovery, heard cues, a seat, body and shape records) are
found by calling the owners on probes (`wire-slice-fields.mjs`). The schema file supplies wire
types only, and refuses an untyped or undeclared field. M's 24 provisioned structures are
derived from the same lists, never from the corpus. Own-player and item records keep source key
order, so they travel inline.

## Candidates

- **D:** a descriptor schema compiled once into one writer/reader closure pair per type, with
  no code generation (`wire-descriptor-codec.mjs`). Optional fields share presence bitmasks,
  and records carry no field identifiers. Numbers are written as integer varints, exact float32
  (only when the value widens back unchanged) or float64. Strings are UTF-8, with a UTF-16
  escape so lone surrogates survive, and a BOM is preserved. Enums and union tags take one
  byte; a const takes none. Decode bounds every length by the bytes remaining and by caps.
  Recursive schemas are refused, so the schema bounds nesting. Truncation, trailing bytes,
  unknown versions or tags, non-canonical numbers and strings, and duplicate map keys are all
  refused. A first, interpretive version decoded about 3× slower than JSON in Chrome, which
  is why D is compiled.
- **M:** msgpackr 2.1.3 records with `maxSharedStructures` equal to the provisioned table, so
  the table cannot grow, and no `sequential`. A 3-byte header (format, version, type) is
  added. The adapter is 33 lines. Node loaded the native `msgpackr-extract` (decode strings
  only); Chrome used pure JS.
- **Controls:** JSON (UTF-8 bytes; `json-string` excludes the UTF-8 conversion) and JSON+deflate
  (zlib default level, 32 KiB window). Deflate is measured per message (self-contained) and with
  per-socket context takeover. Takeover is reproduced by using the socket's previous 32 KiB as a
  preset dictionary, which matches the window contents.

Spectator rows track dev to within a point. The first keyframes are 20.5–20.8 KB as JSON for

server. Per-message deflate costs 2.5–8× JSON's encode CPU. D and M under context deflate both
fall to 5–8%. Compression stays orthogonal to the codec and is not selected here.

## Probes (measurement only)

**Capped packing at 1,200 bytes.** Sections go in priority order: the header and the viewer's
own player and body, then other players nearest first, then changed or keyframe bodies nearest
first. Encoding is one pass with back-patched u16 counts. A record that overflows is rewound,
which re-does one record, never the whole message.
- **Contestants:** D sent the complete slice in 56–59 of 61 messages; M in 28–34. M has to
  pack each record separately, and own-player and item records outside the table carry their
  definitions every time.
- **Gladiators:** both fit essentially everything.
- **Dev and spectator:** neither fit the full set of 11 players and about 11 changed bodies.
  D stopped after 6.4–6.8 bodies and M after 4.8–5.1.
- **Cost:** a capped encode cost about one whole encode (D 7.7–16 µs, M 6.1–14 µs).

This is not datagram fit, fragmentation or a relevance policy (#1094, #1095).

**Quantization.** The probe uses 24.1's candidate quanta for player x/y/heading and body
x/y/vx/vy/angle/omega. Every changed value stays within half a quantum, the largest positional
error being 1/512. Body angle and omega were zero throughout, so this run has no rotation
coverage. Quantized D is 15–25% smaller than exact D. Precision activation stays with #1094 and
29.2.

## Semantics and malformed input

The suite is `wire-codec-safety.mjs`, run on 10 real 12x6 samples and the two specimen
messages, with 99 semantic specimens. The raw report is below.

- **D:** exact on nulls, omitted and `undefined` keys, ID types, -0, safe-integer limits,
  float64 extremes, float32 values, BOM, astral characters, lone surrogates and
  `__proto__`/`constructor` map keys. It refuses an unknown field and strings over 4,096 UTF-8
  bytes on encode.
- **M:** fails the specimens for `undefined` keys, lone surrogates and the `__proto__` map key.
  None of these occurred in the 244 real samples per size.
- **Truncation:** every case throws, for both (14,090 cases for D; 16,681–18,295 for msgpackr).
  So do appended trailing bytes and wrong format, version or type headers.
- **Crafted lengths:** huge lengths (2^31 counts, array32/str32/map32/bin32/ext32) are refused
  in at most 0.03 ms.
- **Nesting:** 100,000 nested msgpack arrays end in a catchable stack-overflow `RangeError`.
  D cannot nest beyond its schema.
- **Random corruption** (2,000 seeded cases): D throws on 79% and returns a different message
  on 21%. msgpackr throws on 45–50% and returns a different message on 50–55%. One provisioned
  corruption reached an internal `TypeError`. No case hangs; the worst decode is 2.1 ms.
- **Control:** the suite's crafted valid descriptor message decodes, so the crafted prefixes
  match the format.

## Limits

- The slice excludes items, gates, traps, projectiles, effects, events, tethers, discovery
  layers beyond the own player, welcome/ready/waiting and map delivery, so whole-message bytes
  and string-heavy item records are not measured.
- The traces come from bots, not human input or prediction. The run is not a GC-pause study,
  not a capacity study and not network loss.
- Node allocation and Chrome allocation are sampled heap profiles (512-byte interval, collected
  objects included), not exact counts.
- D is measurement code, not a reviewed production artefact. #1131 owns its checked
  schema/encoder/decoder emission, version negotiation and full protocol closure (24.1).
