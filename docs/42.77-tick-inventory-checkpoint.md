## Finding

The checkpoint runs the same runtime code as 42.76's end-of-flip runs (`0eb41ff1` plus the profiler labels included in `e0d4dcbe`). The first no-trap run was 0.663 ms above 42.76's range. Its groups were 6–17% slower despite an external busy share of 8%. Both no-trap reruns and one trap rerun were within 42.76's respective ranges. ## Method and limits

Windows, Node 24.15.0 and release core WASM built from `e0d4dcbe`. The 24×12 map used seed 4217 and cache SHA-256 `b13d673b8b5fc101dca36b2b2d27cbc9d15c525a281a902d0b9f5b7a95c37ebe`. The reruns used a cache freshly generated at `e0d4dcbe` and checked against that hash. An older cache in another worktree hashed differently, so a stale cache can silently change the workload. Each headless workload ran five rounds of 300 warm and 600 timed ticks plus snapshots. The table gives the median of the round means for each group, and each rerun range covers two runs. External busy shares were 8.00% and 9.06% for the first runs and 5.4–7.3% for the reruns, all below the 25% cutoff. The comparison with 42.76 assumes the same map because that record predates map hashing.
