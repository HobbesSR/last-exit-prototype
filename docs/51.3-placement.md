# 51.3. Placement (stage 1)

Up: [51](51-generation-chain.md). Shared invariants and vocabulary: [51.1](51.1-principles-and-names.md).

### 1. Placement: seed, params, library → **Layout** (object)

- **Holds:**
  - seed, params and library fingerprint
  - each slot's design and orientation
  - the **set piece instances**: which set piece, of which class, covering
    which slots (`Layout.setPieces`). The old path's layout kept only the set
    piece's id per slot, so two copies of one piece couldn't be told apart.
    Measurement needs to know which class instances were placed, to check what
    their classes promise.

  Nothing else. The primitive grid isn't stored; it's a view (below).
- **Solver:**
  - Set pieces first, as the old path placed them: each class's rule places its quota.
    That rule is what guarantees every owned core element exists.
  - Then WFC for the remaining slots, over adjacency compatibility: a
    neighbour's cell must match each adjacency prescription, or be `any`.
  - Passability prescriptions can't create an adjacency conflict, since neither
    side can require impassable. Reachability checks use their derived guarantees
    ([51.4](51.4-resolution.md)), including `any` meeting `any`. A
    `not-passable-hint` is guidance only: it creates no guarantee or barrier
    requirement. A component can still be pruned for having no possible portal
    path, after both sides' prescriptions and remaining options are considered.
  - Under `matched` passability (a library's `passabilityRules`, 51.4, #849), each seam
    must also fit: `any` or unstated fits anything, otherwise like with like, so `passable`
    against a hint is refused. A set piece whose own slots can't meet is reported before the
    solve (`setPieceSeamProblems`). Each perimeter segment stating `passable` or a hint also
    adds 1 to its design's difficulty, beside each adjacency ask, so constrained tiles are
    placed early (Corey, 2026-11-06, 17.2.2). A slot tries options in descending
    `(difficulty + 12) × random^(1/weight)`: weight is authored, difficulty derived. Under
    matching a design's weight is shared evenly by its allowed orientations (17.2.2).
- **Randomness:** only placement's named streams. The same retry loop, with a
  per-attempt stream.
- **Validity:** every adjacency prescription is met, and no `any` cell is asked
  for two different classes.
- **Reachability:** the open-face rule is the proof's gate and the portal
  rule in incremental form, over guarantees as slots are placed (step 4,
  #113). A placement is refused when it seals a component that isn't the whole
  map, or when it settles a portal shorter than a hunter. So placement never
  returns a layout that `proofViolations` or `portalViolations` would refuse.
- **Search budget:** an attempt gives up after 10 search nodes a cell, or after 500
  open-face refusals without reaching a new depth (`PLACEMENT_STALL_LIMIT`, #849), and the
  next of its 50 attempts starts on its own stream. The budget decides only how long an
  attempt searches, never which layouts are valid (42.37).
- **View, `DeclaredGrid`:** the Layout plus the library gives each cell's
  declared class, and each segment's prescriptions from the design on each
  side, kept separate, not merged.
