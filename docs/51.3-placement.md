# 51.3. Placement (stage 1)

Up: [51](51-generation-chain.md). Shared invariants and vocabulary: [51.1](51.1-principles-and-names.md).

### 1. Placement: seed, params, library → **Layout** (object)

- **Holds:**
  - seed, params and library fingerprint
  - each slot's design and orientation
  - the **set piece instances**: which set piece, of which class, covering
    which slots (`Layout.setPieces`). The old path's layout kept only the set
    piece's id per slot, so two copies of one piece couldn't be told apart.
    Measurement needs to know which class instances were placed, to check what
    their classes promise.

  Nothing else. The primitive grid isn't stored; it's a view (below).
- **Solver:**
  - Set pieces first: each class's rule places its quota, checking `fitsPlacedNeighbours`
    against already-placed neighbors (#856).
    That rule is what guarantees every owned core element exists.
    All picks use stable largest-first order. The landing/evac-first experiment was
    retired after #928; its measurements are in [42.41](42.41-set-piece-order.md).
  - Then WFC for the remaining slots, over adjacency compatibility (`fitsEast`/`fitsSouth`),
    orthogonal dead-end pruning (`WfcConnects` in `map/macro/src/wfc.ts`, #894), and the
    **open-face rule** (`openFaceRule` in `map/macro/src/chain/open-face.ts`, with bounded
    pocket lookahead `LOOKAHEAD_CELLS`, #857): a
    neighbour's cell must match each adjacency prescription, or be `any`.
  - Passability prescriptions can't create an adjacency conflict, since neither
    side can require impassable. Reachability checks use their derived guarantees
    ([51.4](51.4-resolution.md)), including `any` meeting `any`. A
    `not-passable-hint` is guidance only: it creates no guarantee or barrier
    requirement. A component can still be pruned during placement for having no possible
    portal path after both sides' prescriptions and remaining options are considered.
  - Each seam's passability must also fit (51.4, #849): `any` or unstated fits anything,
    otherwise like with like, so `passable` against a hint is refused. A set piece whose own slots can't meet is reported before the
    solve (`setPieceSeamProblems`). Each perimeter segment stating `passable` or a hint also
    adds 1 to its design's difficulty, beside each adjacency ask, so constrained tiles are
    placed early (Corey, 2026-11-06, 17.2.2). A slot tries options in descending
    `(difficulty + 12) × random^(1/weight)`: weight is authored, difficulty derived. A
    design's weight is shared evenly by its allowed orientations (17.2.2). Only a design
    stated `fillable: false` is kept out of the fill (52).
- **Randomness:** only placement's named streams. The same retry loop, with a
  per-attempt stream.
- **Diagnostic trace** (#855): optional event sinks on `placer`, `solveWfc` and
  `openFaceRule` emit detached, serializable deltas without changing choices, draws
  or iteration counts. Attempts include the slot mask and set-piece assignments,
  then collapse/undo events labelled by search depth, refusals with world-cell
  component geometry, cut faces and cause slots, conflicts, backtracking, matching
  contradictions, budget give-ups and outcomes. The Map Lab replays these in its
  Placement tab ([53.1](53.1-map-lab-and-tools.md)); ordinary generation does not
  collect them.
- **Validity:** every adjacency prescription is met, and no `any` cell is asked
  for two different classes.
- **Reachability:** the open-face rule is the proof's gate and the portal
  rule in incremental form, over guarantees as slots are placed (step 4,
  #113). A placement is refused when it seals a component that isn't the whole
  map, or when it settles a portal shorter than a hunter. So placement never
  returns a layout that `proofViolations` or `portalViolations` would refuse.
  - **Lookahead (#857):** the same flood also runs on through unplaced slots and unsettled
    cells, each unplaced slot one node that joins whatever its remaining options could. An area
    that can't reach the rest of the map is refused as soon as that is certain, while it is still
    a hole, not once its last face closes; the cause is the slots that closed its sides, as for a
    sealed component. An area is flooded to the end only while it stays within `LOOKAHEAD_CELLS`
    (32 slots) and `LOOKAHEAD_SLOTS` (8 unplaced slots), which bound each check's cost, not
    validity: a larger sealed area is still refused by the rule above once it closes. Unplaced
    slots are judged optimistically, so a refusal is always sound. Both floods take each placed
    design's fixed parts (cells joined inside it by class or a guaranteed segment) as one node.
- **Search budget:** an attempt gives up after 10 search nodes a cell, or after 500
  open-face refusals without reaching a new depth (`PLACEMENT_STALL_LIMIT`, #849), and the
  next of its 50 attempts starts on its own stream. The budget decides only how long an
  attempt searches, never which layouts are valid (42.37). The limit is a backstop: stalls were
  almost always sealed pockets refused only once their last face closed, which the lookahead now
  refuses when they become certain (#857, [42.39](42.39-reachability-lookahead.md)).
- **Set pieces side by side (#856):** set pieces are pre-assigned before the solve, so each is
  fitted against pieces already placed beside it: placement offers only the anchors, members and
  orientations whose sides fit them (`fitsEast` and `fitsSouth`). A library states this as
  `fitPlacedSetPieces: true`; one that omits it is refused, since placing pieces unfitted, which
  could fail an attempt before its first choice, is retired (#922; adopted in
  [42.44](42.44-sparse-lighting-adoption.md)).
- **Connectivity skeleton (#883):** an opt-in library flag (`connectivitySkeleton`, configured
  with algorithm `wilson`, `prim` or `kruskal`, and `extraOpenShare`) runs `buildSkeleton`
  and `applySkeletonToGrid` (`map/macro/src/chain/skeleton.ts`, up to 5 tries) to draw a
  random spanning tree over the slot multigraph before the WFC fill solve begins. Set pieces
  are collapsed into single nodes connected through their outer openings. The tree's seams
  (and any extra open loops) are marked `:must-open`, admitting only mutually passable options
  at those seams, and `skeletonPartRule` (combined with `openFaceRule` via `bothRules` when
  `filterParts !== false`) prunes options that cannot internally bridge forced-open sides
  through a single connected part. This guarantees a passable connected backbone exists
  upfront, preventing large sealed pockets from forming under sparse tile sides
  ([42.42](42.42-connectivity-skeleton-experiment.md)).
- **View, `DeclaredGrid`:** the Layout plus the library gives each cell's
  declared class, and each segment's prescriptions from the design on each
  side, kept separate, not merged.
