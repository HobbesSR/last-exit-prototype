Up: [42](42-performance-history.md). Design and scaling requirement: [27.2](27.2-tick-architecture.md). Baseline: [42.76](42.76-state-flip-benchmark.md), with the same-session pairing and map hash requested by [42.77](42.77-tick-inventory-checkpoint.md).

## Paired tick and frame

On this map the cutover's tick plus frame was lower in both pairs. These are different simulation rules and bot traces, not an isolated measurement of the tick implementation: in particular bot planning changed substantially. One pair per trap setting does not characterize run-to-run spread. The timer includes counting active contestants and ground records each tick in both versions.

| Median of five round means, ms/tick | End-of-flip | Cutover |
| --- | ---: | ---: |
| No traps: tick + snapshot/frame | 5.831 | 2.886 |
| No traps: bot planning | 3.463 | 1.188 |
| No traps: snapshot/frame | 0.544 | 0.292 |
| Traps: tick + snapshot/frame | 6.242 | 3.042 |
| Traps: bot planning | 3.591 | 0.930 |
| Traps: snapshot/frame | 0.950 | 0.689 |

The no-trap baseline averaged 7.27 active contestants and 816 ground records during timed ticks; cutover averaged 7.64 and 813. With traps the corresponding figures were 7.28 and 815 versus 7.11 and 814. Old discovery as a whole cost 0.597 ms/tick without traps and 0.613 with traps; it is not equivalent to any one of the new discovery subgroups below. New mirror memory refresh alone was 0.030 and 0.029 ms/tick respectively. Labels overlap their enclosing tick and are independently selected medians.

## Ground-record scaling

A separately instrumented scratch build measured the new core's ground collection for discovery, proximity filtering, pickup grid build and pickup queries. It inserts WASM-to-host timer crossings, so these are attribution probes, not production tick timings. Both cases have similar active counts, but different loot distributions and bot traces; they do not hold every other variable fixed.

| Median of five round means | Full map | Quarter of map items |
| --- | ---: | ---: |
| Active contestants, timed-tick mean | 7.64 | 7.57 |
| Ground records, timed-tick mean | 813.33 | 198.67 |
| Discovery ground collection, ms/tick | 0.0415 | 0.0121 |
| Discovery proximity filter, ms/tick | 0.0011 | 0.0005 |
| Pickup grid build, ms/tick | 0.1901 | 0.0518 |
| Pickup queries, ms/tick | 0.0019 | 0.0015 |
| Mirror memory refresh, ms/tick | 0.0295 | 0.0293 |

Ground collection and grid construction grow with the ground-record count here. The grid build is the largest of these measured groups; this is evidence for the spatial-index fallback in 27.2, not proof of its eventual savings. The collection timer covers the production gather when a bot discovery sample needs it; the filter timer covers the per-sample near-ground filter, not all discovery work. The pickup query timer includes the enclosing actor loop, while build includes collection and construction. The memory timer covers core memory decoding and rewriting the mirror, not all mirror work.

## Method and limits

Windows, Node 24.15.0, release WASM. The baseline is the pristine archive of `e0d4dcbe` built with its own core; cutover is the in-progress change measured before the later weapon-quality mirror fix. Both use the same 24×12 cache, seed 4217, SHA-256 `b13d673b8b5fc101dca36b2b2d27cbc9d15c525a281a902d0b9f5b7a95c37ebe`. Each run has five rounds of 300 warm and 600 timed ticks, each with a snapshot/frame. Runs were ordered baseline, cutover, cutover with traps, baseline with traps, instrumented full and instrumented quarter. External busy shares were 7.11–7.98%, below the 25% threshold. The old and new snapshots differ in representation, as do the games they simulate. Results are one map and its bot traces, not capacity estimates.

The trap harness initializes all synthetic trap fields, including default headings, for both sides; these synthetic records previously left some fields undefined, which the new codec rejects. This makes the pair internally matched but limits a direct comparison to 42.76's historical trap run. The reduced map retains the first quarter of the cached items, not a random spatial sample. Profiler hooks and frame counters add overhead, particularly the scratch WASM crossings; small subgroup differences should not be overinterpreted.

Reproduce the main runs with `node tests/bench-phase-three.mjs --root=<e0d4dcbe-archive>` and `node tests/bench-phase-three.mjs`, repeating both with `--traps`. Build the archive's core first. For attribution, run `python tests/bench-tick-attribution.py`, build its scratch core from `test-results/1283-bench-instrumented`, then run the harness with `--root=test-results/1283-bench-instrumented`, once normally and once with `--ground-fraction=0.25`. Use a fresh cache generated from the baseline if the recorded hash does not match. [Raw rounds and contention](reports/issue-1283/benchmark.json).
