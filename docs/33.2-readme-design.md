# 33.2 README and audience guides

Up: [33. Maintenance rules](33-maintenance.md)

This is the design the root [README](../README.md) and its audience guides
should meet. It is the project-specific form of the Foundation Pass's
entry-point track ([33.1](33.1-foundation-pass.md#5-project-entry-points)). The
answers behind it are in [17.6](17.6-foundation-pass.md), items 7–9.

**Status:** target design, not yet met. The README of 2026-11-07 still carries
the full controls table, lab catalog, repository tree, replay and profiling
commands and verification commands. Its status table and demo capture are out
of date.

## Role

The README presents Last Exit as it is now: what it is, who it is for, its
current state and how to get started. It is an overview and a route to further
guidance. It does not hold reference detail or recount history.

## Primary audience

The primary audience is people who want to run the game, either as a host or as
a client. The README gives them:

| Content | Notes |
| --- | --- |
| What Last Exit is | A short premise, who it is for, and current state |
| Screenshots and video | Captures of both the game and the editor or labs; link longer video. A Foundation Pass replaces them only when they misrepresent the game (the current demo predates the generation chain); polished capture waits for a release milestone |
| Host and client quick start | Includes the LAN path |
| Basic rules | How a match works and its objective; link the full rules ([14](14-match-rules.md)) and controls |
| Architecture and repository overview | Brief, with basic development guidance; link the docs index ([00](00-index.md)) |
| Contribution policy | Contributions are not currently accepted; say so plainly |
| Current state and roadmap | A short synopsis linking the maintained sources ([41](41-roadmap.md), [13](13-accepted-features.md)) rather than copying version labels or status tables that drift |

A suggested order, from the scoping session (not separately confirmed):
what it is, see it, run it, how a match works, development at a glance,
contributing and direction, more paths.

## Dedicated guides

These belong in dedicated guides, summarized and linked from the README:

- detailed controls;
- the lab and developer-tool catalog (owned by [20.5](20.5-tools-and-next-boundaries.md));
- verification commands (owned by [31](31-verification.md));
- the complete repository tree.

## Secondary audiences

Each gets its own quick-start guide, linked from a "more paths" route in the
README:

- content authors, who build maps and content with the tools;
- people using the project as the base of a fork;
- the maintainers' own workflow ([34](34-forgejo-workflow.md) and `AGENTS.md`).

An audience guide that belongs beside the README is named `README.<subject>.md`.
Product, engineering and process material stays in the numbered `docs/`
structure, and guides link to it rather than restating it.
