# 42.70. The hook's later rules in the Rust core (#1229)

Up: [42](42-performance-history.md). Design: [27](27-rust-path.md#the-state-flip), step 5d.1. The work is
`rust/core/src/hooks.rs` over `rust/core/src/swept.rs`, driven by `shared/simulation/hook.ts`. `characterization-physics`,
its `-bots` variant and `tests/tick-phases.test.js` passed unchanged.

## Finding

**A hook call costs 2–5 µs in the core.** For a pulling hook, the core is cheaper than the TypeScript was. A flying
hook's reconciliation is a trivial rule, so the crossing is nearly all of its cost. A tick with no hook makes no call.
The relative figure is over 42.58's 10% for that one case, so the step uses
[42.58's state-flip exception](42.58-sight-core-adapter.md#the-budget).

| One hook, one call, mean of 5,000–20,000 | TypeScript (before #1229) | Core |
| --- | ---: | ---: |
| Flying: `reconcileHooks` | 0.10–0.11 µs | 1.80–1.91 µs |
| Flying: `finishHooks` (tip sweep, no actor path) | 6.97–7.06 µs | 4.83–4.85 µs |
| Pulling: `reconcileHooks` (tether revalidated by the solid sweep) | 3.78 µs | 2.13 µs |
| Pulling: `prepareHooks` (revalidation and rope replacement) | 6.24 µs | 4.27 µs |

- **Per tick.** A tick makes one `prepareHooks` and one `finishHooks`, and one `reconcileHooks` per sync. The tick's
  own syncs are three, and drops and pickups add more. One flying hook adds about 5 µs a tick: finish saves about 2 µs,
  and three reconciliations cost about 5 µs more. That is about 0.1% of the mean tick (4.3–4.7 ms, 42.67 and 42.69).
  One pulling hook saves about 7 µs a tick.
- **The exception holds.** The packed state is JavaScript's (the hook records, and the roster the rules read), so no
  flat view can help. The worst case is under 1% of the tick, and this record gives the relative figure beside the
  absolute one.
- **Where the crossing goes.** Packing the roster (six numbers a player), its ID order and, for the tip, five path
  points a player. Then the views and the log. On a real map, the open-gate mask that every call writes adds about
  0.55 µs for 421 gates (42.66). The fixture below has no gates.

## Method

- **Environment.** The development machine (Windows 11), Node 24, the core built with `npm run core:build`.
  2026-11-20. Not under the bench lock, but with no other tests running.
- **The script** was ad hoc and not committed. It used the fixture map of `tests/physics-hook.test.js`: 800 by 800,
  open, no obstacles or gates, one contestant and one hook gladiator. It launched a hook away from the contestant
  (flying) and then one into it (pulling after three ticks). Each rule was timed through the shipped adapter and through
  the retired TypeScript (`git show HEAD:shared/simulation/hook.ts`), with 2,000 warm-up calls. `finishHooks` restored the
  hook records before each call.
- **Limits.** The map is small and open, so the sweeps meet few shapes. The swept query's own cost on the room arena
  is not separately measured here; `tests/swept-core.test.js` holds it equal on the arena. Remeasure with the whole
  tick at #1214.
