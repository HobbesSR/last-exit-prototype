## Sequential crowd comparison

Run `node tools/physics/navigation-report.mjs` after other CPU-heavy work ends.
The retained reports include source hashes, raw per-tick samples, CPU/Node
identity and three sequential paired runs. The scene has 27 bots, 64 crates and
37 sensor loot bodies (128 admitted bodies), with zero combat damage and no
discovery restriction. Each pair compares P6 with P8, including P8's local repair
selection; the timing covers step, snapshot and one player projection. It uses
100 warmup ticks and 400 measured ticks per run.

The [initial report](reports/physics-p8-crowd-initial.json) measured P8 p95 at
25.28/25.61/25.82 ms versus P6 at 4.56/4.19/4.12 ms. The local shape sweep then
gained a conservative bounding-box rejection and avoids computing contact-retreat
distances for already clear shapes. The [final report](reports/physics-p8-crowd.json)
measured P8 p95 at 11.26/11.03/10.83 ms versus P6 at 4.53/4.13/4.10 ms;
P8 p99 was 13.09/11.51/11.22 ms. Peak local search work stayed at 1,275
edges per room tick, below the limit in [14](14-match-rules.md). Both reports
use identical fixture construction. The optimization reduces the observed new
overlay cost, but P8 still costs more than P6 and also changes bot trajectories.

## Verification and limits

The final full root suite passed all 1,087 cases, including the new P8 live-chain
match. `npm run check`, `npm run typecheck`, the 174-case physics suite and the
new/grown file timing checks passed. Full browser coverage passed, including the
new Node/Chrome objective trace; that focused trace was repeated after the query
optimization. The 224-map chain check reported zero drift. No fixture was
regenerated.

After those gates finished, `npm run bench` and then `npm run bench:client`
passed sequentially. The retained raw [server](reports/physics-p8-default-bench.txt)
and [client](reports/physics-p8-client-bench.txt) outputs describe the default
content-5 workload, not P8 qualification. Server seed-4217/12x6 p95/p99 was
4.396/6.512 ms over 2,746 ticks with zero over-budget ticks; the client rendered
720 frames with render-work p95 0.500 ms and frame-gap p95 16.80 ms.

This is bounded local avoidance, not a guarantee of arbitrary long detours around
a persistent crowd or a dynamic global topology rebuild. An unresolvable local
blockage queues and retries. There is no new scenery mutation/destruction API,
loot blocking, crush damage or ordinary movement teleport. The synthetic crowd
sample and one generated full match do not qualify P9 capacity, human feel or
default activation, and do not resolve the historical reported slowdown.
